# curse_of_the_azure_bonds

Scripts for Curse of the Azure Bonds: loading, driving and checking its saves.

| file | purpose |
|---|---|
| `curseareazero.py` | Shows what a Curse save holds before the party begins adventuring: boots C64 Curse to the party-formation menu and reads `$4B00`-`$4DDF`. `--save` and `--begin` load a disk and press `BEGIN ADVENTURING`, reading the KERNAL's `SETNAM` state when the game asks for a disk; `--doctor SRC DST` (offline) stamps the never-adventured header into a copy of a save disk; `--zero` takes the four header fields away one at a time; `--recipe` builds the cache `goldbox.dos_codec.apply_file_cache` would write; `--patch-early` moves `curserun.DISK_PROMPT_PATCHES` back to the party menu. |
| `cursecheck.py` | Boots a Curse save disk in VICE and reads the party off the game's own screens, as `tools/c64/savecheck.py` does for Pool of Radiance: the status line, the roster panel under its `AC` heading (its row count is the party size), every character's `VIEW` sheet, and a walk one key at a time. Records both the status line and the live triple at `$C04B` on every step, since Curse does not print the square in every area. `--resave` has ENCAMP > SAVE write the party back and copies the disk out. Output goes to `--out`; the player's disks are read only. |
| `cursedisk.py` | Builds a Curse C64 save disk from a DOS save folder, which `tools/dos/dosdisk.py` cannot: Curse's container is one 7424-byte `SAVEAZURE` at `$4B00`. Writes it through `goldbox.dos_codec.new_save(game=CURSE_OF_THE_AZURE_BONDS)`, which refuses a payload with an unsourced byte; the combat icon and `ANIMATE00` come off the player's own Curse sides, so it refuses without them. `--check-areas` re-derives the 25 area rows through `tools/areas/areatable.py` and diffs them; `--sheet` prints the DOS party as the C64 `VIEW` screen lays it out. |
| `curseflee.py` | Drives a Curse party into a fight and tries to flee it: `curserun.CurseSession` and `curseload.py` boot and load, and `tools/pool_of_radiance/fleedrive.py`'s `Flight` tactic does the fleeing. Needs `--save` (a Curse save disk) and a pool slot; logs, a screenshot and the final screen go under `--out`. |
| `curseload.py` | Gets a party into Curse through the game's own `LOAD SAVED GAME`, and measures it when it refuses; `load_saved_game()` is the sequence any other Curse tool should call. With no fastloader installed the loader's result is the 1541's own error code at `$03F1`. `--repair` closes a splat entry in the staged copy, `--count` counts calls at `GEN $1F30`, `$183A`, `$1F48` and `$1F4D`, and `--pre-fail`, `--attach` and `--prompt` are differentials described in `docs/179-loading-a-curse-save.md`. |
| `cursememorize.py` | Measures how DOS Curse's `MEMORIZE` list turns a page, for `#574 (Camp.memorize's page-turn landing is stateful and not proven for page > 0)`: stages a specimen party under DOSBox, brings one character to marching position 0, walks `ENCAMP > MAGIC > MEMORIZE` and presses a `--trial` key list from a freshly entered screen, writing a screenshot and the highlighted row, the command bar, the frame digest and the two measured page rectangles after every press. `--after` presses on to a save and prints each record's memorised spells, which is how a `Return` is proven to have committed anything. |
| `cursepaladin.py` | Dual-classes a C64 Curse paladin or ranger through the party menu's `HUMAN CHANGE CLASSES`, trains past the level the old class was left at, and keeps the record `GEN $20A3` writes. `stage` writes ability, level and money inputs into named slots and says which; `run` boots a pooled slot, drives the change, stages the new class's level entry to `dual_class_level` so one training press crosses the regain test, and photographs each keyed screen and the `VIEW` sheet; `show` prints a save disk's class fields with no emulator. |
| `cursepic.py` | Decodes a Curse `PIC` file's animation frames with `ANIMATE00`'s XOR-run unpacker (`$6AC0`) and says which frame a `SAVEAZURE`'s `+$1800`-`+$1BFF` holds. `frames PIC1D --png DIR` renders each frame; `match SAVE.D64 PIC1D` prints, per frame, how many of the 1024 bytes differ, and the matching frame reads 0. See `docs/181-curse-picture-buffer.md`. |
| `cursepicrun.py` | Drives a Curse session to watch the picture buffer: loads a save, overwrites `$6300`-`$66FF` with `$A5`, counts loads and stores of it through the world and a walk, catches the first store on `ENCAMP` with its PC and the load count, then samples the buffer to watch `PIC1D`'s frames cycle. |
| `curseregain.py` | Trains a DOS Curse dual-classed human past the level he left his old class at, under DOSBox, and keeps the record the engine writes: stages a class level, an experience total and the hall's class filter at `SAVGAM+0xD51`, trains roster lines at the party menu, saves with ENCAMP > SAVE, and prints the class fields before and after. `--who 1,6` trains a dual-classed and a single-classed character of the same class in one boot. |
| `curserun.py` | A driven Curse session on a pooled VICE instance: stages the six sides and a save disk, boots past the title, credits and start-up check, answers Curse's three disk-prompt wordings, and patches the disk-swap prompt that cannot otherwise be answered. Curse's move handler answers only the KERNAL buffer, and Curse has no travel grid, so `Session.indoors()` must not read Pool of Radiance's `$49E6`. |
| `cursesavediff.py` | Diffs two Curse `SAVEAZURE` payloads and labels each run of differing bytes with its region and owner: `engine` for a region the game rewrites, `ours` for one where a difference is a conversion fault, `?` for one nobody has attributed. Takes a `.d64` or a raw payload either side, prints payload offsets (add `$4B00` for the machine's address), and exits non-zero while any run lands in a region a conversion writes. |
| `cursethac0.py` | Tests whether a Curse fight reads the stored `thac0_current` or works the number out again. `stage` copies a save disk and writes `0x0A` (THAC0 50) into a named character's roster block, optionally forcing `strength_bonus_flag`; `run` boots a pooled slot, loads through `LOAD SAVED GAME`, walks a route planned from the area's `GEO` passability, presses `PUNCH BARKEEP`, and counts calls at `LIBRARY $3918` and `$394B` to say when the rebuild ran; `show` prints both regions with no emulator. Reads the player's disks only; see `docs/205-the-c64-thac0-rebuild.md`. |
| `cursethiefskills.py` | Explains why a DOS Curse thief's eight stored skills sit seven points above the tables: finds each DOS engine's thief-skill routine in the player's own `GAME.OVR` and reports whether it initializes the stack local it adds to every column, sweeps every Curse record on both ports against that port's tables, and counts which files on the C64 disks draw a thief-skill label. |
| `cursetrain.py` | Stages a Curse save disk with experience, platinum, constitution, class bits, dual-class pair, rolled hit points and per-class levels written into named slots, boots it on a pooled VICE instance, and diffs a before and after record against `goldbox.levelup.plan`. It pokes `$7EA8` to 127 so `GEN $12AF` keeps `TRAIN CHARACTER` in the party menu wherever the party stands. `stage` writes only input fields, `--repair` closes a `SAVEAZURE` the drive never finished, `run` boots and serves rather than pressing keys (`docs/172-curse-trainer.md`), and `diff` prints the field-by-field delta. |
| `cursewarp.py` | Fast-travels a running Curse party: stages the six sides and a save disk into a pooled slot, boots, loads, makes `NEWECL`'s five writes from outside and drops the PC into the handler's tail, then reads back the map at `$0400` and walks a key at a time. Every address is re-derived from Curse's overlays at run time through `tools/areas/newecl.py`. Refuses a warp out of the travel grid without `--force`, since that wedges the loader. |
| `cursewheel.py` | Answers DOS Curse's code wheel from a screenshot, recording neither the challenge nor the answer: matches the two rune tiles at (143,31) and (143,63) against `coab/images/`'s C64-rendered runes, and reads the path cell by cell. The box number is passed with `--box`. The command line prints only `challenge on screen, answered`, `challenge on screen, not answered` or `no challenge on screen`; `answer` and `identify` stay importable. The wheel table comes from `$WISH_CODEWHEEL`, or the `codewheel` entry in `gamedisks.yaml`, outside this repository. |
| `doscurse.py` | Drives a DOS Gold Box session a command at a time out of a text file, with a screenshot after every keypress: the half of the harness `tools/dos/dosbox.py` cannot be, since its digests recognize only screens already known. |
