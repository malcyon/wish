# convert

Scripts for File > Convert: running every conversion direction, hashing what each one writes, and drawing the dialog.

| file | purpose |
|---|---|
| `convertamigadisks.py` | Drives Save As offscreen and writes two POOLSAVE.ADF disks for loading in WinUAE, one from a C64 source and one from a DOS source, both specimens under `$WISH_SPECIMENS`. Needs `--disk` (Amiga Pool of Radiance disk 2); `--out` defaults to `dialog/` in the scratch directory; prints each conversion's report. |
| `convertamigatoc64.py` | Runs an `AmigaToC64` Pool of Radiance conversion through Save As and writes a JSON summary of the specimen hash and each output file's SHA-256. `--tree` runs it from another checkout, `--source-slot L` picks the saved game; offscreen, no emulator. |
| `convertbytes.py` | Hashes, per file, the bytes every registered conversion direction writes, so two commits compare without an emulator: `--tree` measures another checkout, `--diff OLD NEW` names what moved, `--dump DIR` writes one conversion out; a later title's Amiga output is written onto a registry disk 1. Run it in a detached worktree, not the working tree. |
| `convertdialogbuiltshot.py` | Draws the real, built `editor.convert.ConvertDialog` for the six directions and an Amiga source with three saved games onto one captioned sheet, from synthetic sources and the `por-amiga-outdoor` specimen. The counterpart of `convertdialogmockup.py`; needs Pillow, the DejaVu fonts and that specimen. |
| `convertdialogdrive.py` | Converts a DOS or C64 save to an Amiga save disk through Save As and writes a JSON report of the specimen hash, Save As's outcome (or why it stopped) and each written file's SHA-256. Takes `--specimen`, `--amiga-disk2`, optional `--amiga-disk1` (a Curse or Silver Blades output is a copy of it), `--disks` or `--c64-game`, a repeatable `--name POSITION=NAME` to shorten a name the Amiga field cannot hold, and `--tree`; offscreen, no emulator. |
| `convertdialogmockup.py` | Draws the Convert dialog from the compiled `editor.ui_convert` shell in the four-row design, in all six directions, with every string not yet approved marked in the picture. A mock-up, nothing built; needs Pillow and the DejaVu fonts. |
| `convertdrops.py` | Reports what every registered conversion direction says it drops, over every specimen on this machine, calling `Direction.rehearse` as the dialog does and tallying each line against the specimens that reached it; `--reach` crosses each reader's neutral fields with its writer's declared list. Reads specimens from `$WISH_SPECIMENS`, C64 disks through `automap/gamedisks.py` and DOS archives through `tools/dos/dosbox.py`; finds each later title's disk 1 in the Amiga registry images; writes only to a temporary directory. |
| `convertrun.py` | Converts a save through Save As and boots the result: `--to c64` hands the `.d64` to `tools/c64/savecheck.py`, `--to dos` stages the files, loads them with `LOAD SAVED GAME`, walks, and has `ENCAMP ▸ SAVE` write the party back to diff; `--to dos` writes against the source title's own DOS game folder and stops before writing when `--game` holds another title. `--name POSITION=NAME` gives a character the name a destination shows whole; `--leave MEMBER:INDEX` leaves one pack item out when a DOS pack needs more than the C64's sixteen slots; `--leave-effect MEMBER:INDEX` leaves out one running effect when a DOS party needs more than the C64's 64 effect rows; `--no-encounters` holds a C64 Pool of Radiance walk's random encounters off and has the gates put back and verified before the resave; a C64 walk that never moves the party fails the run; `--no-play` stops after the write; output goes to `--out` under the temp directory, never the player's disks. |
| `convertshots.py` | Renders every state `editor.convert.ConvertDialog` can reach to PNGs with `QWidget.grab()` offscreen, so each can be looked at without running anything. States that need the player's DOS save and game disks are skipped, with a line saying so, on a machine without them. |
| `convertsourcesheet.py` | Prints every field of every character the Amiga conversion rehearses from a C64 or DOS source, so the WinUAE screen has values to be read against. Takes SOURCE and `--disk` (Amiga Pool of Radiance disk 2); writes nothing. |
| `hallconvert.py` | Converts one DOS save twice, once with `goldbox.dos_savegame.current_area` patched to read `$49C5` indoors and once as shipped (`$49F2` always), and writes both C64 save disks to boot side by side. `--borrow GEO00` lends a mapless area the map its only caller leaves resident. |
| `nativesavedrive.py` | Copies an Amiga save disk and edits one member's gold, strength and an item quantity through the Character Editor's own Save, offscreen, then reports each value before and after, the backup and whether it equals the pre-edit bytes, and the SHA-256 of base, out and backup. Takes `--base`, `--out`, `--who`, `--gold`, `--strength`, a repeatable `--item POSITION=QUANTITY`, optional `--slot` and `--report`. |
| `podsaveasdrive.py` | Rehearses a DOS Pools of Darkness slot onto the registered Amiga disk 3 and writes the disk image, `saveas-report.json` (specimen, written, `amiga_disk3`, dropped, losses, warnings) and `commit.txt` into `--out`. Takes `--specimen` (the slot's `SAVGAM<letter>.PTY`), `--disk3` and optional `--replace`; offscreen, no emulator. |
| `rewritesweep.py` | Counts the fields of a DOS or Amiga record whose round trip through the editor's C64 record changes bytes, over every specimen and DOS save directory on this machine, saying for each whether the writer rendered more than one value for it and what `write_targets` says it sources it from; `--no-op` rewrites everything with nothing edited and counts what came back byte for byte, `--read-only` fuzzes every field of the C64 record and lists per port the ones no edit moves a byte of, and `--unreachable` lists the fields the writer takes from a constant, a default, a zero or a derivation. Reads specimens from `$WISH_SPECIMENS` and the DOS archives through `automap/gamedisks.py`; writes nothing. |
| `saveasdrive.py` | Opens a save as the editor does, with the Amiga disks it is named, and publishes it through `saveplan.prepare_save_as` and `saveplan.publish`, taking the names a player would choose and reporting a name that did not fit; the other tools here call it. |
