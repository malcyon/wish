# convert

Scripts for File > Convert: running every conversion direction, hashing what each one writes, and drawing the dialog.

| file | purpose |
|---|---|
| `convertamigadisks.py` | Drives `File > Convert...` offscreen and writes the two POOLSAVE.ADF disks step 4 of #36 (Write an Amiga disk image, not just the character files) loads in WinUAE, one from a C64 source and one from a DOS source, both specimens under `$WISH_SPECIMENS`. Needs `--disk` (Amiga Pool of Radiance disk 2, no default); `--out` defaults to `dialog/` in the tool's scratch directory. Prints each conversion's report for the WinUAE screen to be checked against. |
| `convertamigatoc64.py` | Produces an `AmigaToC64` Pool of Radiance conversion through `EditorBinding.convert`, the dialog's own code path, with the dialog accepted and every `QMessageBox` silenced, and writes a JSON summary of the specimen hash and the SHA-256 of each file produced (#52 (File ▸ Import and File ▸ Export for every direction the library supports)). `--tree` runs it from another checkout; `convertdialogdrive.py` is the Amiga-destination twin that records the popups. Offscreen, no emulator. |
| `convertbytes.py` | The exact bytes every registered `File ▸ Convert…` direction writes, hashed per file, so two commits can be compared without an emulator. `#52 (File ▸ Import and File ▸ Export for every direction the library supports)`'s condition 5 -- every direction loaded and walked in its emulator from a save the dialog's own code path wrote -- stays true exactly as long as the bytes it was taken on do, and nothing re-takes it when a writer changes. `--tree <checkout>` puts a detached worktree's `goldbox/`, `editor/` and `tools/` in front of this one on `sys.path`, so the measuring code is this file in both runs and the measured code is each tree's own; `--diff OLD NEW` then says, per direction, how many specimens' output moved and which files inside it. The conversions are `convertdrops.py`'s -- every specimen under `$WISH_SPECIMENS` that `Source.detect` accepts, rehearsed the way `ConvertDialog._rehearse_and_report` rehearses -- and `--dump DIR --only LABEL --source SUBSTR` writes one conversion's files out for a byte-level look. An Amiga destination is hashed by the files **inside** the built `POOLSAVE.ADF`, never by the image, because `AmigaDisk.write_file` stamps wall-clock timestamps and two back-to-back builds of one input differ in about a dozen of 901,120 bytes. Run it against a detached worktree at `HEAD` rather than the working tree: on 2026-09-10 a colleague's uncommitted `goldbox/portraits.py` made three of 118 conversions look nondeterministic. |
| `convertdialogbuiltshot.py` | Draws the real, built `editor.convert.ConvertDialog` for the six directions and an Amiga source with three saved games, from synthetic sources and the `por-amiga-outdoor` specimen, onto one captioned sheet, for `#413 (The Convert window changes shape depending on which platforms you are converting between)`. The counterpart of `convertdialogmockup.py`. Needs Pillow, the DejaVu fonts and that specimen. |
| `convertdialogdrive.py` | Converts a DOS or C64 save to an Amiga save disk through `EditorBinding.convert`, the dialog's own code path, with `ConvertDialog.exec` accepted and the three `QMessageBox` calls recorded instead of blocking, then writes a JSON report of the specimen hash, the popups and the SHA-256 of every file written. Takes `--specimen`, `--amiga-disk2`, optional `--disks` or `--c64-game` for a C64 source and `--tree` to run from a pinned worktree; the `DosToAmiga` Silver Blades and Curse walks and the `C64ToAmiga` Silver Blades walk of #52 (File ▸ Import and File ▸ Export for every direction the library supports) were three copies of this one script. Offscreen, no emulator. |
| `convertdialogmockup.py` | Draws the Convert dialog from the compiled `editor.ui_convert` shell as the chosen four-row design would have it, in all six directions, plus the two open questions (where the Slot row goes, what a C64 destination's third row says), with every unruled string marked in the picture, for `#413 (The Convert window changes shape depending on which platforms you are converting between)`. A mock-up: nothing built. Needs Pillow and the DejaVu fonts. |
| `convertdrops.py` | What every registered `File ▸ Convert…` direction actually **reports** as dropped, run against every specimen on this machine -- the measurement `editor/convert.py`'s condition 8 rests on, since a writer's `DROPPED` tuple is an upper bound rather than a count. `goldbox.neutral.Writer.finish` composes a line only for a field the neutral record actually carries, so a declared entry no source can reach never fires. `goldbox.dos_codec.WRITE_UNREPORTED_DROPS` silenced two that a real C64 source does reach -- `turn_power` and `infravision` -- until `#483 (The Convert flag could come off while two fields are still lost, because a silencing list keeps them out of the count that decides it)` deleted the list on 2026-09-09, so the sweep's count could look emptier than the conversion was; both names, and `encumbrance`, are consumed through `WRITE_NO_SUCH_FIELD` or `WRITE_DERIVED` now. The default sweep calls `Direction.rehearse` the way `ConvertDialog._rehearse_and_report` does, including the **source** title's own combat-icon tables (`#383 (The live Convert dialog never wires a C64 party's own combat icon into DOS, so region_220 stays on the drop list)`, `#422 (A C64 party converted to an Amiga save disk arrives with no combat figure at all, because C64ToAmiga never recognises it)`), and tallies each line against the specimens that reached it -- which is what found the paladin's Protection from Evil on 5 of 10 C64 Curse specimens after a one-specimen run had said the direction was clean. Later-title Amiga container specimens are wrapped in fresh temporary ADFs so their reader paths are measured too, and each Amiga writer receives its own title's game-data disk. `--reach` instead crosses each direction's reader (the neutral fields it sets, over every specimen) against its writer's declared list, and names the entries no registered source carries. Specimens come from `$WISH_SPECIMENS`, C64 disks from `tools/registry/gamedisks.py` and the DOS archives from `tools.dos.dosbox.find_game`; everything is opened read-only and nothing is written outside a temporary directory. |
| `convertrun.py` | Converts a save through **`File ▸ Convert…`'s own code path** and then boots what came out, which is condition 5 of `editor/convert.py`'s flag: *each registered direction has been loaded and walked in its emulator from a save the dialog's own code path wrote*. `tools/dos/dosdisk.py` and `tools/dos/dosnewsave.py` prove `goldbox.dos_codec` by calling `new_save`/`new_dos_save` directly; this drives `EditorBinding.convert(source=…, destination=…, folder=…, game=…)` with every row pre-filled, so no picker opens and the bytes come out of `ConvertDialog` ▸ `Direction.rehearse` ▸ `Direction.write`. `ConvertDialog.exec` is the one thing replaced -- it is the modal wait for a person to press Convert. It prints the pane text a player would be reading first, then `--to c64` hands the `.d64` to `tools/c64/savecheck.py` and `--to dos` copies the written files into a `tools.dos.dosbox` staged tree and loads them through the game's own `LOAD SAVED GAME`, walks, and has `ENCAMP ▸ SAVE` write the party back so the engine's rewrite can be diffed against ours. **A file copy has to clear the slot itself**: `goldbox.dos_codec.new_dos_save` deletes stale `CHRDAT<slot><n>.*` before it moves its own files in, and a freshly staged archive tree carries the shipped party's records at slot A -- thirteen of them on 2026-09-05, including `.ITM` files no conversion writes -- so this repeats that enumeration. It copies **both slots'** `CHRDAT<slot><n>` files out beside the two containers, because the staged tree dies with the session and a `SAVGAM<slot>.DAT` whose party records are gone is a saved game with no party in it. `--no-play` stops after the write. Output goes to `--out`, under the temp directory; nothing is written to the player's disks. |
| `convertshots.py` | Every state `editor.convert.ConvertDialog` can reach, rendered to PNGs with `QWidget.grab()` under `QT_QPA_PLATFORM=offscreen` so Donald can look at every one without running anything (`.claude/rules/gui-text.md`'s "any UI decision requires a screenshot"). Six states — empty, the approved refusal, no C64 disks, no DOS game folder, only `From` filled in, an unreadable source — need only synthetic `SAVGAM?.*`/`CHRDAT?1.SAV` pairs, the same specimens `tests/test_convert.py` builds; the two "ready to write" states need a rehearsal to actually succeed, so they need the player's own DOS save and game disks and are skipped, with a line saying so, on a machine that has neither; two more render the modal `QMessageBox` a real refusal or a name-too-long-for-DOS warning shows in, now that the report pane they used to draw on is gone (2026-09-10) — a row still empty (`NO_FOLDER`, `NO_GAME_FOLDER`, `NO_DISK`, `NO_DISKS`) pops no modal at all since `#52 (File ▸ Import and File ▸ Export for every direction the library supports)`'s fix of 2026-09-10. |
| `convertsourcesheet.py` | Prints every field of every character the Amiga conversion rehearses from a C64 or DOS source, so the WinUAE screen has values to be read against for step 4 of #36 (Write an Amiga disk image, not just the character files). Takes SOURCE and `--disk` (Amiga Pool of Radiance disk 2); writes nothing. |
| `hallconvert.py` | Converts one DOS save twice -- once with `goldbox.dos_savegame.current_area` monkeypatched back to its pre-`#257 (A DOS save made in the training hall converts as though the party were in New Phlan)` expression, `$49C5` indoors, and once as it now is, `$49F2` always -- and writes both C64 save disks so they can be booted side by side. For an area that loads its own map the two words hold the same number and the disks are byte-identical; the training hall and Phlan City Hall load no map, so `$49C5` stays at New Phlan's 0 and the pair differ in `$49F2` and loaded-files cache slot 8. Reproduces the defect from the shipped code rather than from a hand-edited file, which is what makes the booted comparison evidence. `--borrow GEO00` prototypes the fix without touching `goldbox/areas.py`, by lending a mapless area the map its only caller leaves resident. |
