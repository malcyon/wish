# pool_of_radiance

Scripts for Pool of Radiance: driving fights and outdoor walks, and replaying a load failure.

| file | purpose |
|---|---|
| `attackwatch.py` | Presses the attack step next to an enemy in a driven fight, sends nothing else, and polls the screen and the target every quarter second for ten seconds, logging whether the attack resolves, how long it takes and whether `MOVE LEFT` ever moves. Takes an optional log name, save disk, time budget and pool slot; writes `<name>.jsonl` in the scratch directory. It drives an emulator. |
| `defeatdrive.py` | Loses a fight on purpose and reads what the game prints: boots a pool slot, walks into the slums ambush, sets every occupied roster slot's hit points to 1 through the monitor, passes every turn, and records each distinct screen, the program counter (`POST.COM $0957` is `JMP $0957`, so a PC that stays there is a locked machine) and the save disk's SHA-256 either side. `--knock` presses Return and space once at the message. Output goes to `--out`. |
| `dirtenicon.py` | Inspects a Pool save for a uniquely identified joined DIRTEN whose combat icon is entirely zero; `--out` writes a repaired D64 as a new file, never overwriting one. Reads and cross-checks the native default from the player's `POOL3` option data and `POOL1` initialization seed, verifies that only the target icon changes, and prints source and output hashes. Disks come from `POR_DISKS`, then `automap.paths.find_disks()`. |
| `fightrun.py` | Drives one fight from a player's save, unattended: boots a pool slot, loads the save, walks until something ambushes the party, and hands every command bar to `Session.melee_turn`. Writes one JSON line per turn and prints, per character, the turns taken, how many had an enemy in contact and how many of those ended with a blow struck. Data goes to the temp directory. |
| `fleedrive.py` | Runs a Pool of Radiance party away from a fight and reads what the game prints. `code` needs no emulator: it reads each C64 title's `POST.COM` off the player's disks and prints the three end-of-fight lines and the branch that picks the fleeing one. `drive` uses the game's own FLEE by walking each character off the edge of the combat map, then leaves whoever is standing on one hit point and passes turns until the fight ends. |
| `koboldnpc.py` | Watches the Kobold Caves exit take an NPC out of the party, and a fast travel not take her. `walk` steps south through the exit's own script and `warp` enters the new area the way Fast Travel does; both boot the same save disk on a pool slot and end in area 27. Each capture is the eight master slots' names and roster status plus a screenshot, written to `--out` (default the scratch directory). |
| `loadfailurereplay.py` | A VICE driver that fakes the hardware state of a load failure and confirms that the C64 vectors and BASIC interpreter match the failure's recorded screen output. |
| `monstermsg.py` | Shows what the game prints when a monster acts. `table` decodes `COMBAT`'s 64 messages out of `SPELLN00`'s pointer table, `sites` finds every place the overlay prints one and the index it used, `replay` runs a recorded fight through `automap/combatlog.py` with no emulator, and `fight` drives a slums ambush and polls the message panel every 200 ms, recording each message with the acting combatant `$A4F4`, the dice and the names `combat.read_battle` gives. `--delay` pokes the game's combat speed `$49FC`. |
| `movekeysweep.py` | At a live MOVE sub-bar in a fight, presses every candidate key (the eight steps, `KP_5`, `KP_0`, space) and logs one JSON line per press: what was on the destination square, whether the character moved, what the bar said before and after, and whether the target lost hit points. Takes an optional log name, save disk, time budget and pool slot; writes `<name>.jsonl` in the scratch directory. It drives an emulator. |
| `ohlowatch.py` | Drives Ohlo's potion errand in the running game and watches the Quest Log row follow it: boots a save with the party in the Slums, walks to the booth at `GEO14` (15,12) and on to Ohlo's block, and renders `QuestLogPanel` offscreen from the live `$4900`-`$64FF` read at each stage, sampling `$4A81` every 0.4 s and holding `$4A80` at its cap of 15 so no wandering fight interrupts. None of the game's words are in the file: they are unpacked from `ECL14` on the player's disk at run time. `rows` renders the panel from a captured window with no emulator. |
| `outdoorstep.py` | Takes one compass digit at a time on the travel grid and prints row 24 verbatim before `MOVE`, after `MOVE` and after the key, beside `$49C3`/`$49C4`, `$49C0`-`$49C2`, `$49E6`, the clock and the area, with a screenshot of each: it says why a step was refused, where `outdoorwalk.py` says which digit went where. `--boat STAY` (the default) declines the boat, because `TAKE` sails the party back to New Phlan; each digit is tried by XTEST and then through the KERNAL buffer; `--resave` has ENCAMP > SAVE write the party back and copies that disk out. Output goes to `--out`; the player's disks are read only. |
| `outdoorwalk.py` | Walks a party on the C64 travel grid one key at a time, photographing the frame before and after each press, to show which digit went where. Reads `$49C3`/`$49C4` through the binary monitor rather than the lagging status line, and polls rather than sleeping. The overland move bar is `1-8, RETURN OR BUTTON`, the compass clockwise from north (1 N, 3 E, 5 S, 7 W), not the dungeon's `I J K M`; `tools/c64/session.py` and `tools/c64/savecheck.py --walk` also walk an outdoor party. |
| `porattract.py` | Runs Pool of Radiance's opening attract loop in a pooled VICE and watches for a stall: boots `POOL1.D64`, answers `DISABLE FASTLOADER (Y/N) ?`, then sends nothing, because leaving the `PLAY GAME` menu alone starts the demo. Samples the program counter, the screen and the jiffy clock, and on a stall dumps the registers, the stack page, both CIA ports and the bytes around the PC. Opens one monitor connection per sample, since a connection held across the loop stops the emulator. |
| `slumsquitprobe.py` | Drives one Slums ambush in a pool slot with the shipped `melee_turn` and, the first two times a sub-bar has no GUARD, presses QUIT instead, logging the mode byte, the acting index at `$A4F4` and rows 22-24 every 0.4 s, plus whether each character took MOVE that turn. Takes NAME, SAVE, BUDGET and SLOT; writes `<name>.jsonl` in the scratch directory. Boots VICE. |
| `sokolarrivalcheck.py` | Claims a pool slot, stages the Pool disks and a save that arrives at Sokol Keep (the boat scene) into it, boots, loads, begins adventuring, prints each step's result and the status, and screenshots where it ended up. Its offline half is `tests/c64/test_arrivalscene.py`. Takes the save as its argument; boots an emulator. |
| `worldregisters.py` | Reads the chips while a party stands on the travel grid: boots one outdoor save like `tools/c64/c64outdoor.py` and reads `$D011`/`$D016`/`$D018`/`$DD00`, `$D020`-`$D023`, the screen matrix, `$D800` colour RAM, the camera `$037E`, the loaded-files cache `$6E13`-`$6E2B` and `$49C5`, and the resident window `$8C00`. Finds the pane by matching every 3 x 3 block of screen codes against the window's 120 tiles, with no camera assumed; `--compass` presses `1`-`8` and reads `$033D` around each. Measurement B of `docs/217-drawing-the-wilderness.md`; writes nothing to the player's disks. |
| `worldtiles.py` | Draws the 120 wilderness tile pictures the way the C64 draws them, from the player's own disks: `goldbox/world.py`'s nine screen codes and attributes, the glyphs out of `SECSET04`/`05`/`06`, attribute bit 3 selecting multicolour over hi-res, and the three shared colours in `$D021`-`$D023` that `worldregisters.py` reads off the chip. `sheet`, `view X Y`, `codes X Y`, `census` and `sample` (the whole wilderness and a 16 x 16 piece at two sizes each, for choosing how the automapper draws it) are the commands. Measurement A of `docs/217-drawing-the-wilderness.md`; pictures go under `--out` and are never committed. |
