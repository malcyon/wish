# records

Censuses and cross-checks over character records that span titles and ports, such as class combinations, fields and encumbrance.

| file | purpose |
|---|---|
| `boundarychars.py` | Builds deliberately extreme *Pool of Radiance* characters for `tests/records/test_boundary.py`, each a `NeutralCharacter` read as though off a C64 disk, which is what a real conversion into DOS sees. |
| `boundarywidths.py` | Builds the boundary characters and field ranges for `goldbox.c64_codec.write`: every scalar at its lowest and highest value and one past, the name, and the memorised-spell, spellbook, item and trait-slot ceilings of each title, for `tests/records/test_boundary_c64.py`. |
| `carryceiling.py` | Counts how close any real character gets to the two limits a conversion might have to tell a player about, the sixteen item slots in a C64 record and the ten trait slots at `0x0AD`. Sweeps every C64 disk, DOS archive, played save directory, specimen and Amiga disk image on the machine and reports the widest inventory and fullest trait list per port, title and provenance grade. `--json` writes one row per character, `--grants` the effect-granting item templates, `--items` the DOS `item_count` histogram. |
| `classcodecensus.py` | Counts the records whose class code disagrees with the classes they hold levels in, per port and per title. The bits-to-code table is read out of Curse's C64 `GEN` at `$1951`, and the mask is derived from the level array, with DOS's stored mask folded through `goldbox.dos_codec.neutral_class_bits` first. Reads the specimen tree and, with `--archives`, the player's archives; writes nothing. |
| `classcombocensus.py` | Counts, per port and title, which class combinations the character records hold and how many store a dual-class old level, over the specimen tree, the Pool disks and the shipped archives plus any `--c64-root` and `--dos-root` given. Counts what exists and is not evidence about the game. Read only. |
| `classcombocheck.py` | Asks, of every record it is pointed at, whether the editor's Class combo would draw the class a conversion writes. Calls the shipped `editor.window._char_class_shown` and `goldbox.c64_codec.read`, shows the stored `class_bits` beside the bitmask the level array implies, and converts a DOS record through `goldbox.dos_codec.to_neutral` and `goldbox.c64_codec.write` first. Exits 1 on a disagreement; writes nothing. |
| `classlegality.py` | Reads off both ports of Pool of Radiance which classes each race may take at character creation, the table `goldbox/levels.py` does not carry and not the racial level limit. Both table addresses come out of the C64 `GEN` menu builder's own operands, and DOS keeps the same matrix as seven counted, strictly increasing class-code lists found by content. Reads the player's own disks and archives; with neither port present it prints nothing and exits 0. |
| `compare.py` | Loads every character specimen and reports, per record offset, how much the value varies, so the offsets that vary are candidate fields to correlate with attributes already known. No emulator needed. |
| `controlbyte.py` | Reports the Gold Box control byte on both ports at once, C64 `0x0B8` and DOS `0x084` (`0x0F7`, `0x0FF`, `0x147` in the later titles), whose bit 7 says the engine drives this character. Partitions the records on the machine by value with the reading beside each; the low seven bits are a morale percentage stored halved, so `$B2` prints as morale 100. The DOS offset comes out of each title's own structure and the finder is `tools/dos/dostailcensus.py`'s; `--disk` adds a C64 image outside the registry. `tools/dos/dosbyteimm.py` reads what an engine stores there. Reads only. |
| `doswidths.py` | Builds the boundary characters and field ranges for `goldbox.dos_codec.write` in all four titles it writes: every numeric target read off the writer's own tables, the names the writer recomputes with its reason, and a sentence for each numeric field that is not a plain width, for `tests/records/test_boundary.py`. |
| `enccensus.py` | Sweeps the `money + Σ(weight × quantity)` encumbrance identity over every DOS and Amiga record on the machine, each graded by where it was found and whether its item file is present. `--stacks` finds item stacks whose cached display line disagrees with the quantity byte, `--pair` diffs two save directories one game action apart. |
| `fieldcensus.py` | Censuses one named record field over every character record on this machine, knowing nothing about what the answer should be; `thac0census.py` does the same for `thac0_base`. Three record sets, each named in the header line: `c64` (the player's save disks plus the title's own specimen disks, matched by filename prefix), `dos` (the specimen tree, the archives and the player's folder, with `--all-titles`), and `monsters` (Pool of Radiance's `MON<hex>` files, whose body is a character record at offset 0). Nothing is written; the disks are opened read-only. |
| `geoplausible.py` | Re-takes the measurement behind `automap.area.looks_like_a_map`. `maps` scores every `GEO` file and `GEO.GLB` block on the disks this machine has; `sweep` scores every 1024-byte window of every other file, which the thresholds are calibrated to reject; `thresholds` prints, for each constant, the worst real map beside the best non-map that clears the other three clauses. It imports `map_evidence` rather than recomputing anything. |
| `geoports.py` | Diffs the same Gold Box map between the ports that shipped it. `diff` pairs the C64 `GEO<id>` files, the Amiga `GEO.GLB` library and the DOS `GEO<n>.DAX` blocks by area id and decodes every differing byte (plane, square, and whether it is wall art, a barrier, a roofed bit or a script id). `closest` measures both sides of `automap.area.NEAR_ENOUGH`, the widest gap between two ports' copies of one area and the closest two different places, and exits non-zero when the tolerance does not fit between them. `blocks` lists every DOS `GEO<n>.DAX` block in the archives with the two bytes in front and the four quantities `looks_like_a_map` measures. |
| `infravision.py` | Shows where a Gold Box character's infravision comes from and what a conversion does with it. `table` reads the race-indexed table the C64 character generator writes record `0x0D5` from, off the player's `GEN` overlay, and prints the four instructions that use it; `read` prints every occupied slot of a save with its race, stored byte and what the generator would have written; `stage` copies a save disk and sets the byte to a value the character's race does not imply, so a load-and-resave in the running game shows whether the engine recomputes it. Nothing here writes to the player's disks. |
| `laterchars.py` | Builds legal Curse of the Azure Bonds and Secret of the Silver Blades characters at their class and spell ceilings for `tests/records/test_boundary_c64.py`: one per race and class entry either creation menu offers, one per pair the dual-class route can leave, and the deepest caster each title can reach, which in both is a dual-classed human holding two spell lists at once. |
| `laterlegality.py` | Reads off Curse's and Silver Blades' own C64 overlays which classes each race may take at creation, which classes each alignment may change to, and Silver Blades' spell-slot rows, and reports the deepest caster either title allows. The three menu tables come out of the builder's own operands, the alignment table out of the `HUMAN CHANGE CLASS` handler's, and the slot rows out of `ECL65`'s self-modifying filler. Reads the player's own disks; writes nothing. |
| `spellbookcensus.py` | Partitions every character record on this machine, on all three ports, by what its book of known spells holds, in particular whether anything sets Pool of Radiance's spell id 56, `RESTORATION`, which the DOS record has a byte for at `0x06A` and the C64's seven-byte mask at `0x078` has no bit for. `--control` re-asks over every DOS record file raw, with no deduplication or exclusions. Reads the C64 mask past the title's own width and the memorised list at the width `tools/c64/memorisedwidth.py` measures, and flags a title `goldbox/spells.py` has no table for. Each row is graded `built`, `spec`, `edited` or `found`. Reads only. |
| `thac0census.py` | Checks every stored `thac0_base` on this machine against the port's own THAC0 table and the rule that port's engine applies to it. `tables` prints both ports side by side with the DOS level-0 column, `c64` and `dos` sweep every record -- `dos` covers all three DOS titles and prints what the engine's own recompute gives beside what the table alone gives -- and `code` prints every `mov dx,<stride> / mul dx / ... / mov al,[di+off]` site in `GAME.OVR`. The C64 table comes off whichever `POOL*.D64` carries `GEN` and the DOS one out of the EXEPACK-expanded `START.EXE`, so neither is hardcoded and the read cannot agree with `goldbox/levels.py` by construction. Reads only. |
| `thiefskillcensus.py` | Checks every stored thief skill on this machine against the port's own tables. `tables` prints all three blocks per port, `rows` puts the racial rows side by side and measures the byte-stream shift between them, `c64` and `dos` sweep every record, and `--rule` says which rule each record fits. The C64 tables come off whichever disk carries `GEN` and the DOS ones out of the EXEPACK-expanded `START.EXE`, located by the C64's own 72 bytes of level table; two structural checks confirm the geometry. Reads only. |
| `traitnames.py` | Shows what a title's own shipped data says an effect code means, beside the name `goldbox/traits.py` gives it. The default spell audit reads the per-spell record through `tools/c64/traitquery.py` and prints every code one of the title's spells writes, with the spells, the combat message, the spell group and our current name. `--monsters` reads the ten bytes at record `0x0AD` of every `MON<hex>` template and reports which codes each holds, `--against TITLE` puts another title's carriers beside them, and `--records` prints one row per template. Needs no emulator or save; the disks are read-only. See `docs/171-c64-trait-slots.md`. |
| `turncensus.py` | Lists every C64 character record on the machine with the turning byte at `0x0A4` beside the one the title's own `GEN` would compute from its cleric and paladin levels, and exits non-zero when any record disagrees. `--dos` asks which DOS records carry anything at `0x076`, the undead's row rather than the caster's. See `docs/178-turning-undead.md`. |
| `xpceiling.py` | Asks whether a DOS character's experience can pass the C64 record's three bytes: `check` reports, per title, the 32-bit `add`/`adc` that accumulates the running total in the game's own `GAME.OVR` and the largest constant any instruction compares the field's high word against, `sites` lists every instruction touching the field, and `convert` pushes a real record with a chosen experience through `goldbox.dos_codec.to_neutral` and `goldbox.c64_codec.write`. Archives are read only. |
