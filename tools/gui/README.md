# gui

Scripts that draw or measure Wish's own windows, and the Windows guest scripts that run them.

| file | purpose |
|---|---|
| `automapfightwindow.py` | Drives a live Pool of Radiance fight in a pool VICE slot while the assembled `AutomapBinding` polls on its own `QTimer` through a `TransientTarget` that opens the binary monitor fresh for every read, and logs every line the Messages panel gains as JSON lines: the whole-window measurement #350 (The Messages window logs the party's attacks and dice but nothing a monster does) had not taken. Stages `PORSAVE13.D64` from the player's disks; `--out` and `--budget` (or `$WHOLEWINDOW_BUDGET`) as arguments. |
| `automappoll.py` | Measures the two automapper complaints on one pooled slot: how often the CPU's PC sampled while the party stands still falls outside the Fast Travel key-wait windows (which is the button's flicker rate, `#152 (The Fast Travel button greys itself out for a second while the party stands still)`), what a second monitor attach does and how long it takes while one is held, and whether the emulator keeps running after a connection is dropped without `EXIT` (`#151 (The automapper loses VICE and cannot get back in, because it never hangs up the connection it gave up on)`). Boots from `PORSAVE11.D64` in `$POR_DISKS`; `--slot` and `--out` choose the slot and where `results.json` goes. It drives an emulator. |
| `bigfont.py` | Opens the real program with N points added to the interface font, on the desktop, so a layout question can be answered by dragging the window rather than argued from numbers. `shotwindow.py` photographs the window offscreen and captions its floor; this one is for when the question is what happens when somebody *pulls* on it, which is what `#97 (The character editor tab gets taller as the UI font grows, so a large font stops the window fitting a 720-high screen)` turned out to be. **It puts a window on the screen**, so it is for a person at the machine and never for an unattended agent. `docs/160-why-these-rules.md` records +6 here measuring about like Windows' base font, and +10 as the largest worth caring about. |
| `bodychoices.py` | Draws the three bodies `#480 (An Amiga character whose body is the menu's eighth arrives on the C64 or DOS wearing a different body, because the Amiga reader uses the C64 and DOS menu)` is a choice between, so it can be decided by looking rather than by reading art ids -- what DOS and the C64 draw for creation-menu position 8, what the Amiga draws for the same position, and what writing 33 into the Amiga record reaches off the end of its menu table. Donald, 2026-09-10: *"I have no idea what you're talking about. I would need to see screenshots."* `--menu` adds both ports' twelve menu bodies in menu order and `--all` adds every body block each port ships, which is the picture that shows the drawing DOS gives position 8 is in none of the Amiga's twenty-one blocks -- an id on both disks is not a picture on both disks. Every panel is an art block off the player's own disks, the Amiga side through the game's own screen palette; the PNGs go under the temp directory, because they are the game's own pictures. |
| `combatbarsheet.py` | Draws the combat map's square as a **letter over a miniature health bar** -- the shape Donald settled for `#345 (Draw a letter in each combat-map square saying what is standing there, instead of the index the backend counts with)` on 2026-09-06 -- so the look can be chosen from a picture rather than a description. Three candidate looks side by side (`paper`, a white bar with a faint track; `signal`, coloured green to amber to red; `bare`, the white bar and nothing else), at every cell the canvas paints (12, 20, 30, 40 and 66 px), for a party member at full, half, nearly dead and zero, a monster labelled `DF`, the gold helpless fill, an unreadable occupant and the four-letter label the table replaced. `closeup.png` is the 12 and 20 px rows at four times, and `canvas-*.png` is the real `CombatCanvas` drawing the synthetic arena through the same function, at the window's minimum, its hint and 1400 x 900. Sizes the letter in pixels to the room above the bar and prints what each label landed at, because the size below which a letter stops being readable is a measurement rather than a formula. Touches nothing in `automap/`; whichever look is picked moves into `CombatCanvas._draw` afterwards. Output goes to the tool's scratch directory, or to `--out DIR`. |
| `combatlabelroomshot.py` | Draws the combat canvas offscreen with candidate labels (`F/MU`, `C/F/MU`, `7LDF` ...) standing in for the hit points, at its minimum size, its size hint and 1400x900, and prints the cell size and font size each used, for `#345 (Draw a letter in each combat-map square saying what is standing there, instead of the index the backend counts with)`. Built on `tests/gamedata`'s synthetic arena, so no emulator and no game disk. |
| `combatshot.py` | Draws the automapper's combat canvas and prints what it was drawn from -- all four effect arrays raw, the effects running, who the reader calls helpless, every combatant, and **every combatant's tooltip**, which a `grab()` does not paint. Reads a running machine, or builds `tests/gamedata`'s arena with `--synthetic` so the drawing half can be looked at with nothing booted; `--helpless` marks a combatant in that made-up memory, which is the only way to see the badge, since no save this project holds carries one. Exists because the two halves mislead separately: a canvas that draws nothing and a machine with no fight running make the same PNG. Rescued from the helpless-badge run (scratch, deleted). |
| `editorshotdivider.py` | `shotwindow.py` with two more arguments: photographs the character editor offscreen at a UI font (`--font`), a window size (`--size`) and divider heights (`--rows`), with a caption of those numbers, into the PNG named, for #97 (The character editor tab gets taller as the UI font grows, so a large font stops the window fitting a 720-high screen). Runs on a synthetic save; no disks needed. |
| `effectshot.py` | Photographs the active-effects panel offscreen, with effects composed into the save image in memory -- no save disk on this machine has anything running. `#13 (Edit traits and active effects, in two separate panels)`. |
| `levelupstubhit.py` | Prints the Level up button's width, visible region and state at the 220px column, then which widget a hit test finds under the button every four pixels. A probe for #168 (A character ready to level loses the Level up button, even with nothing running). Offscreen, writes nothing. |
| `licensesshot.py` | Photographs Help > Licenses offscreen at the base UI font and at 6 points more, writes `licenses-0pt.png` and `licenses-+6pt.png` under `--out` (default the tool's scratch directory), and prints the size the dialog was shown at with its `sizeHint` and `minimumSizeHint`, which a caption cannot say. Drops `WAYLAND_DISPLAY` and forces the offscreen Qt platform before it makes the application, so nothing opens on the desktop. |
| `livecheck.py` | Runs the automapper tab's **own code** against a running game and reports it feature by feature, which is what `#34 (Validate the live automapper tab per title)` asks for and what nothing did before: `--title por\|curse\|ssb` boots that title on a pooled VICE slot from a save disk in the specimen tree, gets the party into the world, and then calls `automap.state.Automapper.poll()`, `automap.live.read_snapshot`, `automap.live.badges` and the five `automap.actions` buttons. Nothing is re-derived -- a tool that reproduced any of those its own way would be measuring itself -- so each check is `pass`, `fail` or `unreached` about the shipped path, one JSON line per event as it happens plus an SVG of the map that got drawn (whole, and explored-only). Three checks **stage a byte first**, because no save this project holds carries the situation: a wound in front of Heal party, roster `+0x0C` bit 7 in front of Quickfight off, an item's hidden-name bits in front of Identify, and a memorised spell id in front of Save/Restore spells. The staged byte is the input and the button's own code is still what is measured; without it those checks report "nothing to do" and call it a pass. It carries four things about driving this that cost a boot each: the screen's registers are read through `automap.vice.banked` and never through the processor's view (`#336 (The screen reader goes blind on the insert-a-side prompt, and every screen-driven recovery fails with it)`, `#421 (The automapper reads the screen through the CPU's banking, so it reads the wrong memory while the game loads)`); `$XDG_DATA_HOME` is **not** reassigned to redirect the run's map notes, because a Flatpak user installation lives under it and moving it makes `tools/c64/porlaunch.sh` fail with `app/net.sf.VICE/x86_64/master not installed`; every session is told which title it is driving, since `tools/secret_of_the_silver_blades/ssbwarp.py`'s `SSBSession` does not (`#426 (The session driver will not walk a Silver Blades party, because SSBSession never says which title it is)`); and the actions run before the walk, because a walk starts fights and every action is refused in one. `--boundary` crosses an area boundary with `automap.actions.FastTravel` and reads the area byte and the resident map either side. The player's disks are copied into the slot and read only; output goes to `--out`, under the temp directory. |
| `livestrip.py` | Photographs the automapper's party-effects row from a **running** emulator's own memory rather than from a made-up effect table: one poll's two blocks off a pool slot's binary monitor, the `Snapshot` the automapper would build from them, and the row drawn from that. It prints the whole effect table as well, because a row that draws nothing and a machine with nothing running are the same PNG. Written to answer `#142 (The party effects line is computed every poll and shown nowhere)` in the game rather than in a test. |
| `mapmarker.py` | Photographs the automapper's **own** map window while a driven party walks, which is the only way to answer what a player looking at the map sees rather than what memory says. It boots a save on a pool slot with `tools/c64/session.py`, builds `wish/window.ui`'s map tab offscreen through `AutomapBinding` -- the same canvas, strip and Messages panel the program ships -- reads its fix with `automap.target.party_fix` over the same monitor in one stop/resume, and saves the window, the canvas and the emulator's own screen after every step, beside the bytes that explain them (`$49E6`, `$49C0`, `$49C3`, `$C04B`, `$6E1B`) and the verbatim status row. Written for `#198 (Does the automapper draw a live party on the travel grid, or leave the marker where it entered?)`; it takes `--walk` in the dungeon's `I J K M` or the travel grid's compass digits, and keeps its settings and notes under `--out` so a run never touches the player's own. `--home` brings the party back *off* the grid, which the window's own Fast Travel refuses and which needs `$49E6` written to 1 before the jump; with `--place` and `--arrival` it can put the return square one step from the outdoor one, which is the crossing `#205 (A party that walks out onto the travel grid leaves the automapper's marker behind)` had to photograph. |
| `messageshot.py` | Photographs the automapper's Messages panel with a proposed line in it, because a sentence that reads well as a constant can read badly behind the timestamp the panel puts in front of every line. Builds the real window offscreen, drives an arena through a short fight so the panel holds what a player would be reading, and grabs it. `--say "One line."` may be repeated, and with none it photographs the warning built for `#425 (The Messages window logs a quarter of a fight when the player turns the game's combat speed up)`. It needs no emulator and no game disks. |
| `monitorchain.py` | Drives the automapper's give-up-and-reconnect chain against a real VICE, with no game and no disks: poison a `ViceTarget` the way a stalled machine does, then ask what `fix` raises, whether `close()` closes, what the next attach sees and how long it takes, and whether a timed-out read leaves the stream out of step. `#151 (The automapper loses VICE and cannot get back in, because it never hangs up the connection it gave up on)` was a fault of exactly this kind -- `close()` guarded on a flag every give-up path cleared first -- and no offline check could see it. Measurements in `docs/96-live-memory-automapper.md`. |
| `monsterlabels.py` | The combat map's **monster labels** for `#345 (Draw a letter in each combat-map square saying what is standing there, instead of the index the backend counts with)`: at most two characters above each monster's health bar, chosen by hand because no rule turns `7TH LVL DW FIGHTER` into the `DF` Donald wants. Reads every `MON*` file on the three C64 titles' disks through `gamedisks.yaml`, `--propose` appends a draft row to `monsterlabels.yaml` for every name that has none (first letter of each word, skipping ordinals, numbers and `LVL`, first and last when more than two remain -- a guess to correct, never rewriting a row already there), and `--markdown` writes the document to read the table by: one table per title with every name, its files, its hit dice, its label and which other names share it. Collisions are fine and listed so they can be seen. The plain run reports names with no row, rows with no monster, and labels over two characters. Nothing of the game's is written anywhere. |
| `monsterlabels.yaml` | The monster-label table itself, one quoted row per `MON*` name with its quoted label and a comment saying which titles carry it and its hit dice. **Donald edits this by hand**; `monsterlabels.py` only appends and reads. Quoted throughout because `ON`, `N` and `Y` are booleans to YAML bare. Our judgement rather than the game's data, so it is committed; the 206 rows of 2026-09-06 are `--propose`'s draft and none is approved yet. |
| `portraitmontage.py` | Tiles the same rectangle out of several screenshots into one picture, which is how six character sheets answer "did each character arrive wearing its own face" -- six separate frames do not, and a repeated face is obvious in a strip and invisible across six files. `--rect left,top,width,height` cuts the emulator's frame down to the sheet, `--across` tiles left to right, `--scale` magnifies with nearest neighbour. Output goes under the temp directory: these are the game's own portraits and they are not committed. |
| `rostercard.py` | Puts an automapper roster card into a state no saved game can produce -- so many condition badges lit, a full hand readied, ready to level, at a chosen column width and interface font -- and says where each part of it ends up: whole, cut (N of Mpx), or gone past the column's edge. No save on this machine has a character with every condition running, so the states that decide the layout cannot be photographed from one; this writes them by hand, as `shotstrip.py` does for the effect table. It is what settled `#161 (Five condition badges push the class, the level and the Level up button off the roster card)` and `#168 (A character who has earned a level shows 32px of the Level up button)`, and now it is how somebody asks whether they have come back. Offscreen, no game disks needed. Built from the harness the twelve scripts in `cited/161/` shared. |
| `rostercardvariants.py` | The harness the `rostercard*` and `levelupstub*` scripts share, from #161 (A roster card loses a character's classes and its Level up button once four condition badges are lit): one character built through the real `WishWindow`, offscreen with a scratch config directory, plus the helpers that render a widget and stack captioned pictures into one PNG. A library, not run on its own; `rostercard.py` was built from it and is the one to run today. |
| `rosterfloorshot.py` | Photographs the window's minimum width with an ordinary six-character party open, at the base UI font and at +6, under today's `min(natural, ROSTER_MIN_WIDTH)` and under the three shapes `#474 (Raising the UI font grows the window's minimum width with an ordinary party open, which is the defect #41 removed for the widest one)` names. `EditorBinding._size_roster` is monkeypatched onto the class in memory for one window's construction and never written to disk, so it runs safely while `editor/window.py` is somebody else's file. Prints each shape's measured width and height beside the path of its picture; `cited/474/` has the eight this produced on 2026-09-10. |
| `screenblind.py` | Watches what the screen reader reads against what the VIC was actually showing, one JSON line per poll, and stages the failure on purpose. Written for `#336 (The screen reader goes blind on the insert-a-side prompt, and every screen-driven recovery fails with it)`: the reader took `$D018` and `$DD00` off the monitor's **default** bank, which is whatever the CPU can see, and Pool of Radiance's loader spends part of every load at `$01 = $30` with the I/O chips banked out -- so those two reads are bytes of RAM and the screen is computed somewhere nothing is displaying. It boots a driven session with every poll instrumented and logs both banks' answers side by side; on slot 0, 2026-09-07, four polls of 1,035 disagreed, all four putting the screen at `$C000` where the chips said `$DC00`. Four in a thousand is not something to wait for, so `--stage` writes `$30` to `$01` **with the machine stopped**, reads the screen through `automap.vice.read_screen` and through `tools.c64.drive.read_screen`, and puts `$01` back before a cycle passes -- at the main menu, at the world command bar, and in the poll that first sees the insert-a-side prompt, which is where the old reader answered `..@@@@....@@@@..` and the new one answered `INSERT SIDE # 3, AND PRESS ANY KEY.` The player's disks are copied into the slot and read only. |
| `shotstrip.py` | Photographs the automapper's roster column offscreen with a made-up set of party-wide spells running, and prints the icon row's tooltip, which a `grab()` does not draw. Exists because `shotwindow.py` runs with no emulator, so the party effects row is always empty in it — and because **no save this project holds carries a party-wide effect**, so the only way to look at that row at all is to write the effect table by hand. |
| `shotwindow.py` | Photographs the whole window offscreen at a chosen UI font size and width and writes a PNG, with the floor and the width actually drawn captioned on the picture and a marked line where a target width falls. Exists because `#71 (Character draws on top of itself when the header is squeezed to its floor)` was decided by looking at three of these and not by reading `minimumSizeHint()`: a number cannot say whether a squeezed header draws on top of itself. `--font +6` measures here about like Windows' base font, so a Windows-sized layout can be seen without a Windows machine. Defaults to the synthetic widest party, so it runs with no game disks. |
| `taskbaricon.py` | Draws **every square mark the artist delivered, resized and nothing else**, at the sizes a Windows `.ico` is asked for -- 16, 20, 24, 32, 48 and 256 -- each at true size on a light taskbar and a dark one and magnified beside it, for `#351 (The Windows build shows no logo in About and a black square on the taskbar, because the artist's SVGs are not in the package)`. | `traitshot.py` | Photographs the Character Traits box, its picker and the filtered picker, for `.claude/rules/gui-text.md`'s rule that an interface decision comes with a picture of it. Reads `PORSAVE11.D64` through `tests/gamedata.py` and works on a copy. |
| `winwish.py` | Runs Wish in the Windows 11 VM on this machine so a person can look at the real window at Windows' own font size: `setup` takes the lease, installs Python and PyQt6 and unpacks the working tree, `measure`, `start`, `stop` and `status` run in the guest's session 1 through `winvm`. It sends `winwishsetup.ps1`, `winwishtask.ps1`, `winwishmeasure.py` and `winwishrun.py` to the guest. |
| `winwishmeasure.py` | Runs inside the Windows 11 guest and measures the editor window's minimum width on the real `windows` platform plugin and `windows11` style at +0, +3, +6 and +10 points, for an ordinary six-character party and the widest party the record allows, and leaves the ordinary party's disk for `winwishrun.py`. The Windows counterpart of `rosterfloorshot.py`'s Linux measurement, taken for #474 (Raising the UI font grows the window's minimum width with an ordinary party open, which is the defect #41 removed for the widest one). |
| `winwishrun.py` | Runs inside the Windows 11 guest, started by `winwishtask.ps1 -Action start` in the guest's session 1, and opens Wish's editor window on the ordinary-party disk `winwishmeasure.py` wrote, with stdout and stderr pointed at `C:\Wish\window.log` because `pythonw.exe` has no console. `winwish.py` copies it to the guest; what it looks at is the window of #474 (Raising the UI font grows the window's minimum width with an ordinary party open, which is the defect #41 removed for the widest one). |
| `winwishsetup.ps1` | Runs inside the Windows 11 VM: downloads and installs per-user Python 3.12 from python.org if the guest has no real interpreter (the PATH one is the Store alias), unpacks the repository archive into `C:\Wish\wish`, creates a venv and installs PyQt6, pyyaml and pytest; touches nothing of the Amiga or VICE lanes. `winwish.py setup` puts it there and starts it; written for `#474 (Raising the UI font grows the window's minimum width with an ordinary party open, which is the defect #41 removed for the widest one)`. |
| `winwishtask.ps1` | Runs inside the Windows 11 VM through Interactive scheduled tasks named `wish-*` so the window lands on the visible desktop and not in session 0: `-Action measure` registers a task that runs `winwishmeasure.py` and prints `C:\Wish\measure.txt`, `start` opens the editor on the ordinary party with `winwishrun.py` and leaves it up, `stop` closes it, `status` shows the tasks, the Python processes and `quser`; the task registration is `tools/amiga/winuae.ps1`'s, copied on purpose, and the Amiga lane is never touched. Driven by `winwish.py`; written for `#474 (Raising the UI font grows the window's minimum width with an ordinary party open, which is the defect #41 removed for the widest one)`. |
