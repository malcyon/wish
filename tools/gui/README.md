# gui

Scripts that draw or measure Wish's own windows, and the Windows guest scripts that run them.

| file | purpose |
|---|---|
| `automapfightwindow.py` | Drives a live Pool of Radiance fight in a pool VICE slot while the assembled `AutomapBinding` polls on its own timer, and logs every line the Messages panel gains as JSON lines. Stages `PORSAVE13.D64` from the player's disks; takes `--out` and `--budget` (or `$WHOLEWINDOW_BUDGET`). |
| `automappoll.py` | Measures automapper polling on one pooled slot: how often the sampled PC falls outside the Fast Travel key-wait windows, what a second monitor attach does while one is held, and whether VICE keeps running after a dropped connection. Boots from `PORSAVE11.D64` in `$POR_DISKS`; `--slot` and `--out` choose the slot and where `results.json` goes. It drives an emulator. |
| `bigfont.py` | Opens the real program with N points added to the interface font, on the desktop, so a layout can be judged by dragging the window. It puts a window on the screen, so it is for a person at the machine and never for an unattended agent. |
| `bodychoices.py` | Draws the bodies an Amiga character's creation-menu position 8 can arrive as on the C64 or DOS, so the choice can be made by looking. `--menu` adds both ports' twelve menu bodies and `--all` every body block each port ships; the PNGs come from the player's own disks and go under the temp directory. |
| `combatbarsheet.py` | Draws the combat map's square as a letter over a miniature health bar in three candidate looks (`paper`, `signal`, `bare`) at every canvas cell size, plus the real `CombatCanvas` at its minimum, its hint and 1400 x 900. Touches nothing in `automap/`; output goes to the scratch directory or `--out DIR`. |
| `combatlabelroomshot.py` | Draws the combat canvas offscreen with candidate labels standing in for the hit points at three window sizes, and prints the cell size and font size each used. Built on `tests/gamedata`'s synthetic arena, so no emulator and no game disk. |
| `combatshot.py` | Draws the automapper's combat canvas and prints what it was drawn from: all four effect arrays, who is helpless, every combatant and every tooltip, which a `grab()` does not paint. Reads a running machine, or builds `tests/gamedata`'s arena with `--synthetic`; `--helpless` marks a combatant in it. |
| `editorshotdivider.py` | Photographs the character editor offscreen at a UI font (`--font`), a window size (`--size`) and divider heights (`--rows`), captioned with those numbers, into the PNG named. Runs on a synthetic save; no disks needed. |
| `effectshot.py` | Photographs the active-effects panel offscreen, with effects composed into the save image in memory. Needs no save disk with anything running. |
| `levelupstubhit.py` | Prints the Level up button's width, visible region and state at the 220px roster column, then which widget a hit test finds under the button every four pixels. Offscreen, writes nothing. |
| `licensesshot.py` | Photographs Help > Licenses offscreen at the base UI font and at 6 points more into `--out` (default the scratch directory), and prints the dialog's shown size, `sizeHint` and `minimumSizeHint`. Forces the offscreen Qt platform, so nothing opens on the desktop. |
| `livecheck.py` | Runs the automapper tab's own code against a running game and reports `pass`, `fail` or `unreached` per feature: `--title por\|curse\|ssb` boots that title on a pooled slot and calls `Automapper.poll()`, `read_snapshot`, `badges` and the five `automap.actions` buttons. Where no save holds the situation it stages one byte as input; one JSON line per event plus SVGs of the map. `--boundary` crosses an area boundary; the disks are copied into the slot and read only. |
| `livestrip.py` | Photographs the automapper's party-effects row from a running emulator's own memory: one poll's two blocks off a pool slot's binary monitor, the `Snapshot` built from them, the row drawn from it, and the whole effect table. |
| `mapmarker.py` | Photographs the automapper's own map window while a driven party walks: boots a save on a pool slot with `tools/c64/session.py`, builds the map tab offscreen through `AutomapBinding`, and saves window, canvas and emulator screen after every step beside the bytes that explain them. `--walk` takes `I J K M` or the travel grid's compass digits; `--home`, `--place` and `--arrival` set up a return to the grid; settings and notes stay under `--out`. |
| `messageshot.py` | Photographs the automapper's Messages panel with a proposed line in it, behind the timestamp the panel adds, after driving an arena through a short fight. `--say "One line."` may be repeated; with none it photographs the combat-speed warning. Needs no emulator and no game disks. |
| `monitorchain.py` | Drives the automapper's give-up-and-reconnect chain against a real VICE with no game and no disks: poisons a `ViceTarget`, then reports what `fix` raises, whether `close()` closes, what the next attach sees and how long it takes, and whether a timed-out read leaves the stream out of step. Measurements are in `docs/96-live-memory-automapper.md`. |
| `monsterlabels.py` | Builds and checks the combat map's monster labels (at most two characters each) from every `MON*` file on the three C64 titles' disks, read through `gamedisks.yaml`. `--propose` appends a draft row to `monsterlabels.yaml` for each name without one, `--markdown` writes a review document per title, and a run with no option reports names with no row, rows with no monster and labels over two characters. Writes nothing of the game's. |
| `monsterlabels.yaml` | The monster-label table: one quoted row per `MON*` name with its label and a comment naming the titles that carry it and its hit dice. Edited by hand; `monsterlabels.py` only appends and reads. Quoted because `ON`, `N` and `Y` are booleans to YAML bare. Committed because it is our judgement, not the game's data. |
| `portraitmontage.py` | Tiles the same rectangle out of several screenshots into one picture, to compare the faces on several character sheets: `--rect left,top,width,height`, `--across` and `--scale` (nearest neighbour). Output goes under the temp directory, because the portraits are the game's own. |
| `rostercard.py` | Puts an automapper roster card into a state no save can produce (many condition badges lit, a full hand readied, ready to level) at a chosen column width and interface font, and reports where each part lands: whole, cut (N of Mpx), or past the column's edge. Offscreen; no game disks. |
| `rostercardvariants.py` | The library the `rostercard*` and `levelupstub*` scripts share: one character built through the real `WishWindow` offscreen with a scratch config directory, plus helpers that render a widget and stack captioned pictures into one PNG. Not run on its own. |
| `rosterfloorshot.py` | Photographs the window at its minimum width with an ordinary six-character party open, at the base UI font and at +6, under the current `min(natural, ROSTER_MIN_WIDTH)` rule and three alternatives, and prints each width and height beside its picture's path. `EditorBinding._size_roster` is patched in memory for one window and never written to disk. |
| `screenblind.py` | Compares what the screen reader reads with what the VIC is showing, one JSON line per poll. `--stage` writes `$30` to `$01` with the machine stopped, reads the screen through `automap.vice.read_screen` and `tools.c64.drive.read_screen`, and restores `$01` before a cycle passes. The disks are copied into the slot and read only. |
| `shotstrip.py` | Photographs the automapper's roster column offscreen with a made-up set of party-wide spells running, and prints the icon row's tooltip, which a `grab()` does not draw. The effect table is written by hand because no save carries a party-wide effect. |
| `shotwindow.py` | Photographs the whole window offscreen at a chosen UI font size and width, with the minimum size and the width drawn captioned on the picture and a marked line at a target width. `--font +6` approximates Windows' base font. Defaults to the synthetic widest party, so it needs no game disks. |
| `taskbaricon.py` | Draws every square mark from the logo delivery, resized and nothing else, at the sizes a Windows `.ico` is asked for (16, 20, 24, 32, 48, 256), at true size on a light and a dark taskbar and magnified. Reads the delivery in place from `~/Downloads/wish_logo/` (`$WISH_LOGO_DELIVERY`) and copies nothing in; `--measure` prints the SVG-versus-PNG gap and `--shipped` draws what `ui.appicon.image` produces. The sheet goes to the scratch directory. |
| `traitshot.py` | Photographs the Character Traits box, its picker and the filtered picker with `QWidget.grab()`, so no window reaches the desktop. Takes the output directory as its one argument; reads `PORSAVE11.D64` through `tests/gamedata.py` and works on a copy. |
| `winwish.py` | Runs Wish in the Windows 11 VM so the real window can be seen at Windows' own font size: `setup` takes the lease, installs Python and PyQt6 and unpacks the working tree; `measure`, `start`, `stop` and `status` run in the guest's session 1 through `winvm`. Sends the `winwish*` guest scripts to the guest and does not drop the lease. |
| `winwishmeasure.py` | Runs inside the Windows 11 guest and measures the editor window's minimum width on the real `windows` platform plugin and `windows11` style at +0, +3, +6 and +10 points, for an ordinary six-character party and the widest party the record allows. Leaves the ordinary party's disk for `winwishrun.py`. |
| `winwishrun.py` | Runs inside the Windows 11 guest, started by `winwishtask.ps1 -Action start` in session 1, and opens the editor window on the disk `winwishmeasure.py` wrote. Stdout and stderr go to `C:\Wish\window.log` because `pythonw.exe` has no console. |
| `winwishsetup.ps1` | Runs inside the Windows 11 VM: installs per-user Python 3.12 if the guest has no real interpreter (the PATH one is the Store alias), unpacks the repository archive into `C:\Wish\wish`, and creates a venv with PyQt6, pyyaml and pytest. Touches nothing of the Amiga or VICE lanes; `winwish.py setup` sends and starts it. |
| `winwishtask.ps1` | Runs inside the Windows 11 VM through Interactive scheduled tasks named `wish-*`, so the window lands on the visible desktop and not in session 0: `-Action` is `measure`, `start`, `stop` or `status`. Driven by `winwish.py`; the task registration is `tools/amiga/winuae.ps1`'s, and the Amiga lane is never touched. |
