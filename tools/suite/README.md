# suite

Scripts that run and check the test suite: the whole-suite run that gates a push, the generated test party, the rules check, the sys.path census and the pytest plugins that chase a flaky guard test.

| file | purpose |
|---|---|
| `conftestflake_analyze.py` | Summarises the logs `conftestflake_probe.py` writes: merges every worker's CREATE/DELETE events for the two probe files `tests/test_conftest_state_guard.py::_run_throwaway_test` writes and removes, and says whether the two probes' lifetimes overlapped and for how long. Used to measure how often that overlap happens under the project's real `-n auto --dist loadgroup`: 20 of 20 runs overlapped, ~300ms out of ~330-390ms each probe was alive. |
| `conftestflake_force_group.py` | Diagnostic-only pytest plugin for `#522 (A conftest guard test fails at random on the Windows 3.13 job, so a red main no longer means the commit broke something)`: applies `xdist_group` to both tests in `tests/test_conftest_state_guard.py` at collection time, without editing that file, to check by experiment whether grouping them would serialise them onto one `pytest -n auto` worker. It does -- 0 of 20 runs overlapped once forced, against 20 of 20 without it -- but needed `@pytest.hookimpl(tryfirst=True)` to run before `pytest-xdist`'s own `pytest_collection_modifyitems`, a hazard specific to adding the marker via a hook rather than a real fix's `pytestmark = pytest.mark.xdist_group(...)`, which binds before any hook runs at all. |
| `conftestflake_probe.py` | Diagnostic pytest plugin for `#522 (A conftest guard test fails at random on the Windows 3.13 job, so a red main no longer means the commit broke something)`: watches `tests/` for the appearance and disappearance of the throwaway probe files `tests/test_conftest_state_guard.py`'s `_run_throwaway_test` writes and removes, without changing that file at all, logging each event's timestamp and worker id. `conftestflake_analyze.py` reads what it writes. |
| `conftestflake_windows_repro.py` | Pytest plugin for `#522 (A conftest guard test fails at random on the Windows 3.13 job, so a red main no longer means the commit broke something)`: forces the race deterministically instead of waiting on `pytest -n auto`'s scheduler. Resolving a single-file argument under `tests/` collects the *whole* directory first, which on `win32` falls back to `_pytest.pathlib.samefile_nofollow()` -- an unguarded `.lstat()` -- for every sibling whose path does not string-equal the target's. This deletes a chosen sibling right after `tests/`'s own collect report is produced (`ISSUE522_MODE=force`) or leaves it alone (`ISSUE522_MODE=control`), and logs both of `samefile_nofollow`'s arguments plus any exception, so a failure can be attributed to the actual pair of paths rather than assumed. `.github/workflows/flake-measure-conftest-guard.yml` drives it on Windows; proven once already by faking `sys.platform` to `win32` for the collection phase only on Linux -- 10 of 10 `force` runs failed collection naming the sibling, 10 of 10 `control` runs passed. |
| `pathleak.py` | Which `tools/` scripts leave `tools/` on `sys.path` after import, and which of those capture the name `wish` when run as a file. 34 of 119 and 7 at `c1bbe6f`; the count is what `#259 (A cold test run intermittently loses the wish package to tools/wish.py, and a different test fails each time)` was about |
| `rulescheck.py` | Asks where every rule and every quotation in the old 1595-line `CLAUDE.md` ended up after `#208 (Split CLAUDE.md into .claude/rules, so 21,800 tokens do not load before every task)` broke it into `.claude/rules/*.md` and `docs/160-why-these-rules.md`. Reads the old file straight out of git and reports what no longer appears anywhere: a missing quotation of Donald's is an error, a missing bolded imperative is a prompt to check whether it was reworded or dropped. A split done by hand across three agents can lose a paragraph and still look tidy. |
| `suiterun.py` | **The one whole-suite run before a push**, as a single command: a detached worktree at the given sha with `gamedisks.yaml` symlinked in, then `pytest`, `ruff` and `tools/generate/genui.py --check` all inside it, and only if all three pass, `~/.cache/wish/testrun/<sha>.green` -- the marker `.claude/hooks/check-push-tested.py` requires before it lets a `git push` through. `test-runner` runs this rather than the three checks by hand, so the marker is written by the command that saw them pass. |
| `testparty.py` | Generates the six-character high-level test party of `docs/119-test-party.md` from code alone, in about a second, with no emulator and no game bytes: a level-1 record per character through `goldbox.c64_codec.write`, then `goldbox.levelup.plan` once per level with experience granted before each training, so every derived byte above level 1 comes from the training hall reproduced rather than from a table this tool reads. `--rolls max` hands the trainer an rng that always rolls the top of the die, which is what reaches the documented ceilings -- BULWARK at THAC0 13, 112 hit points and 3/2 attacks -- and makes the party byte-identical every run; `--rolls min` and `--rolls seeded` are the other two. `--records DIR` writes one 582-byte `.CHR` export per character and `--disk PATH` puts all six on a **copy** of the player's save disk, slots and roster blocks both, never touching the original. The one thing it cannot make is the combat icon, and the test file fails if a second gap ever appears. `tests/test_testparty.py` rebuilds each of the six characters the engine rolled in `WISH-SPEC-por-party-l1-rolled` from its own inputs and compares, which is what stops the generator validating its own tables. |
| `testpartyrun.py` | Boots a `testparty.py` disk in a pool slot and reads all six character sheets off the screen, which is `docs/119-test-party.md` §6's third gate and the only one that is evidence about the game rather than about our tables: the level, experience, hit points, armour class and THAC0 come back through the game's own sheet routine and its own charset. Six of six agreed on 2026-09-08, BULWARK included -- LEVEL 8, EXP 130000, HITPOINTS 72, AC 8, THACO 11 -- which is what turned the fighter ceiling from our specification agreeing with itself into a measurement. Stages the generated save beside symlinks to the player's own sides so the originals are only read, photographs each sheet while it is up, and writes one JSON line per event to `run.jsonl` as it happens. Two things it knows that the next driver needs: the party panel is in marching order, so index 0 is the *last* save slot, and the sheet's portrait window reads back as a charset ramp through `Session.screen()` because the portrait is a bitmap over the text matrix. |
