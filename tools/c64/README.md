# c64

Scripts for the Commodore 64 titles: the VICE session and the drivers built on it, save and record checks, and the C64 Ultimate tools.

| file | purpose |
|---|---|
| `abilitypair.py` | Stages a copy of a save whose two ability arrays (`0x014` and `0x065`) differ and prints both beside the bytes the engine derives from them, to show which one the engine uses; `docs/201-the-two-ability-arrays.md`. |
| `absrefsweep.py` | Lists which of a title's files name an address in an absolute window, counting art files and script bytecode apart from the overlays; `--sites` disassembles around each hit. |
| `backstab.py` | Reads all six C64 titles' backstab gate, multiplier, damage multiply, to-hit adjustment and dual-class regain path from the player's own overlays; `docs/225-the-dos-backstab-multiplier.md`. |
| `bamsweep.py` | Reads the BAM disk header (track 18 sector 0, bytes 144-255) of every `.d64` given, or of `$POR_DISKS`, and counts how many match `docs/10-disk-format.md`; reads only. |
| `c64addchar.py` | Drives ADD CHARACTER TO PARTY on a pool slot with load watchpoints on record bytes `0x0E4`-`0x0E9` to show what reads `0x0E6`-`0x0E7` and what the add screen tests; never writes the player's disks; `docs/170-c64-identity-pair.md`. |
| `c64addprobe.py` | Drives ADD CHARACTER TO PARTY on a pool slot against the Curse save disk given with `--save`, taking `--remove NAME` out of the party first if asked, and prints the disk's directory after each step and the name inside the picked file, to show what the add list matches on and whether the file is still there afterwards; screens and disk copies go under `--out` and the player's disks are never written; `docs/216-the-c64-name-table.md`. |
| `c64clock.py` | Finds the six-digit game clock in every C64 title's overlays from its tick loop and status line, saying which save page each title writes and the limit each digit rolls at. |
| `c64monsterlabelcensus.py` | Reads the name in every `MON*` file on the three C64 titles' disks and applies the first-letter-of-each-word combat label rule, reporting counts, longest labels, punctuated names and labels two names share; reads only. |
| `c64nametable.py` | Shows what the `+$C00` party-name table on Curse and Silver Blades is for: `show` compares it with the disk's character files, `sites` finds the `$5700` instructions in `GEN`, `run` reads `$5700`-`$57FF` live around ADD CHARACTER TO PARTY. |
| `c64outdoor.py` | Makes an engine-written Pool of Radiance C64 save standing on the travel grid by seeding from an indoor disk (never written), walking the party in VICE and taking ENCAMP > SAVE; the twin of `tools/dos/dosoutdoor.py`. |
| `c64portraitprobe.py` | Reads the loaded-files cache at `$6E13` while a sheet is up to say which portrait art the C64 game fetched, patching the staged save or live RAM so a run differs from the last by one byte. |
| `c64recordoperandsweep.py` | Counts the absolute, absolute,X and absolute,Y operands that land in a window of the character record (`$7C00` Curse and Silver Blades, `$6B00` Pool), per file, over one title's disks; a byte scan that reads only. |
| `c64restinterrupt.py` | Says whether a C64 rest can be interrupted where the party stands: `code` reads the gate and every area script's entry 2 off the disks, `drive` counts rest checks and interruptions live; writes nothing to the player's disks. |
| `c64savescan.py` | Prints one line per `.D64` in the Pool of Radiance disks folder, the `SAVEDGAME0` area file and each occupied slot as `NAME(Cn/MUn/Fn)`, or the error for an image that is not a save disk; reads only. |
| `c64savespells.py` | Prints each occupied slot's name, levels, experience, `hp_max` and raw `spells_memorised` and `spells_castable` bytes for named Pool of Radiance save disks, the detail view after `c64savescan.py`; reads only. |
| `c64sheet.py` | Prints a C64 save's party as a character sheet, every field read through `goldbox.c64_codec.read`, so it can be set beside the DOS sheets of `tools/dos/dosdisk.py --sheet`; reads only, all three titles. |
| `c64splicechar.py` | Puts one DOS character record into a slot of a copy of a C64 save disk (record, roster block, item slots, combat icon) so a race no C64 disk holds can be converted back; `--icon default` composes the game's icon. |
| `c64strength.py` | Reads `THACO` and `DAMAGE` off the C64 sheet with record byte `0x0E3` set and clear, putting one converted character in five party slots that differ only in it, to show whether the flag gates the strength bonus. |
| `c64todoswalk.py` | Walks a C64-to-DOS Pool of Radiance conversion in DOSBox: copies the converted `CHRDAT<slot>*` files into a fresh folder, loads the slot, steps up to eight times and saves over slot D; claims one DOSBox pool slot. |
| `c64u.py` | Drives the C64 Ultimate through the `c64u` CLI (mount a staged disk, DMA reads, paused dumps with bank state in a JSON sidecar, the automapper's poll blocks); refuses flash, reset, poweroff, streams and ui; exits 3 with no device. |
| `c64ucompare.py` | Reads one manifest of memory regions off both a C64 Ultimate and a pooled VICE and diffs them, masking colour registers and free-running addresses and optionally walking VICE to the hardware's square. |
| `c64uhang.py` | Reproduces the C64 Ultimate load hang with no game, from a generated one-line BASIC loader and 4 KB data file, firing host `readmem` reads during the load and naming where the processor sat on a hang; `build`, `run`, `sweep`. |
| `c64uload.py` | Runs one polling experiment against Pool of Radiance on the C64 Ultimate (a treatment for a fixed time, then a hang verdict from the jiffy read twice ten seconds apart); `stress` loads the HTTP service with no boot. |
| `c64uplay.py` | Drives a game on the C64 Ultimate and captures a hang: waits on keys through `$00C6`, polls screens, bursts frames, and `hangwatch` dumps ten memory regions when nothing moves; `docs/177-a-load-that-goes-wrong.md`. |
| `c64urest.py` | Does the C64 Ultimate's disk jobs over `urllib` and `ftplib` with no `c64u` CLI (upload, mount, boot from the first PRG, FTP fetch, read screen RAM, write the keyboard buffer); touches no device configuration. |
| `coldread.py` | Reads one title's own tables off its disks with no emulator, each found by the instruction that reads it: `GEN`'s racial-trait seeds, class caps, race limits and the overlays that touch the four active-effect arrays. |
| `combatdiag.py` | Drives a fight through the shipped `Session.melee_turn` unchanged and logs each turn's candidate squares, key chosen and waits to JSONL, which `read` renders; the live counterpart of `stepcheck.py`. |
| `combatsigs.py` | Re-derives from each C64 title's own files where `COMBAT` keeps the message printer, the four text-window bytes and the message-delay byte, printing every delay candidate and marking the one at save byte `$FC`; reads only. |
| `curedisease.py` | Reads where C64 Curse and Silver Blades keep a paladin's cure-disease and lay-on-hands uses (record `0x012`/`0x013`), what seeds and gates them and which effect-array timer resets them, reads the same rule out of DOS Curse and Silver Blades (`dos_inspect`) and what their HUMAN CHANGE CLASSES leaves of it (`dos_class_change`), and gives the C64 bytes that play a DOS paladin's uses and node back (`c64_cure_write`); `records` prints both bytes for each paladin on the saves given; reads only; [`docs/234`](../../docs/234-a-paladins-cure-disease-across-dos-and-the-c64.md). |
| `curedrive.py` | Stages a paladin's cure uses and cure-timer rows into a copy of a C64 Curse or Silver Blades save (`stage`), then boots it on a pool slot and plays a script of camp `VIEW` sheets, `CURE`, exact-length rests and saves, reading `0x012`, the rows, the clock and three checkpoint counts at each step (`run`); `summary` prints a run's readings; [`docs/234`](../../docs/234-a-paladins-cure-disease-across-dos-and-the-c64.md). |
| `d64census.py` | Lists the disk header name and id of every D64 in a tree, and every character file by filename prefix, load address and the title `c64_port.detect` reads; `header` and `files` modes, defaulting to the registry's disks. |
| `d6502.py` | A small 6502 disassembler: given a raw overlay image, a load address, a start address and an instruction count, prints addresses, bytes and mnemonics; `docs/148-d6502.md`. |
| `d6502check.py` | Checks `d6502.py` against capstone over every byte value and over whole overlays, with `BRK` excepted by declaration; capstone stays a cross-check rather than a dependency, so this is a tool and not a test; `docs/148-d6502.md`. |
| `diff.py` | Diffs two save disks and says what changed in game terms: each changed byte resolves to a slot and record offset, labelled with its layout field or flagged as an unknown region. |
| `dispelread.py` | Reads each C64 title's Dispel Magic routine off the disks -- the ids it tries, the predicate it asks, its level test and chance, its removal -- to say whether it can reach a trait slot; no emulator; `docs/230-who-reads-a-dos-effect-node.md`. |
| `drive.py` | Drives Pool of Radiance under VICE: the binary-monitor client (re-exported from `automap/vice.py`), key sending through XTEST on the nested display, and the discovery scaffolding. |
| `dualclassagain.py` | Tests whether a Gold Box character can change class twice: `dos` installs a dual-classed save and sweeps the roster or presses the command in DOS Curse or Silver Blades, `c64` attempts it in VICE; `docs/176-changing-class-twice.md`. |
| `dump.py` | Annotated dump of a `.D64`, a save game or a `.chr`: disk directory, save summary, one character record, or a raw address range. |
| `effectcrosswalk.py` | Reads duration packing from three C64 engines and compares Pool of Radiance's effect ids and values with DOS, identifying exact duration candidates and unproven mappings; `docs/226-the-c64-running-effect-crosswalk.md`. |
| `effectdrive.py` | Measures what an active effect's duration byte counts and what its magnitude restores: writes one effect per value of bits 6-7 into a copy of a save disk, walks and rests, and counts the ageing, expiry and restore routines with non-stopping checkpoints; `docs/133-active-effects.md`. |
| `flags0b8.py` | Classifies every instruction in the six C64 titles that touches record byte `0x0B8` -- bit-7 tests, the morale read and its clamp, the trainer flag, the script joins, the berserk pair and the import reset -- and censuses the byte in each title's `MON*` files; reads only; `docs/232-the-c64-control-byte-per-title.md`. |
| `hallmenu.py` | Steps a converted party off the training-hall square and photographs every screen the game puts up, classifying row 24 and answering each; `--answer NO` declines training; output goes to `--out` under the temp directory. |
| `inventorycheck.py` | Edits a Curse or Silver Blades inventory through the editor's own handlers, then reads it off the game's item screen in VICE; `stage` and `run`; `docs/139-per-title-validation.md` A13. |
| `laterbattle.py` | Proves a Curse or Silver Blades fight in VICE and drives one (Curse at Tilverton's tavern, Silver Blades by waiting for a wandering monster), probing the combat pages raw; `--melee`, `--quick`, `--keys`, `--accept`. |
| `latercombat.py` | Holds where each C64 title keeps a fight as data (mode byte, roster, initiative table, save head, record slots, result byte, message delay, dice) and re-exports the names now in `automap/combat.py`; an unmeasured title gets None. |
| `laterfight.py` | Walks a converted Curse or Silver Blades party into a fight and reads the combat screen over an already served session's command port; `--quick` uses the game's quickfight, `--survey-bars` records each bar offered. |
| `laterrolls.py` | Corroborates Curse's d20 store and attack block (`$A915`, `$9458`-`$9463`) live in a driven Tilverton fight, reading both before combat and after every `QUICK` turn; subclasses `laterbattle.py`. |
| `laterthac0.py` | Locates the later DOS titles' THAC0 tables without knowing a THAC0 number, which `tools/records/thac0census.py` cannot; `table`, `compare`, `records` and `writers`; reads only; `docs/210-the-later-titles-dos-thac0.md`. |
| `libslots.py` | Prints the loader's twenty-five file slots off `LIBRARY` (filename stem, load address, whether the overwrite scan may mark it dirty), generating the table in `docs/140-loaded-files-cache.md`; no emulator. |
| `livelevel.py` | Raises a character's level on a running machine by replaying what the training hall writes through `automap.actions.LevelUp`; the machine is left doctored, so never save it over a game you want to keep; `docs/135-levelling.md`. |
| `livemem.py` | Dumps a range of a running pooled session's memory to a file, for what a one-line `peek` cannot answer: an item area, a page of two-bit patterns, a whole `GEO`. |
| `livewatch.py` | Sets a load, store or exec watchpoint on a running pooled session, reports the program counter, return addresses and code around the hit, then removes it. |
| `loadrace.py` | Stages a stray space keypress at the LOAD SAVED GAME: YES bar (choose, settle, send one space, then do what `Session.load_save` does next); `--no-space` is the control. |
| `memorisedwidth.py` | Reads how wide a title's memorised-spell list is out of its own `CAMP` (the count-down loop's immediate and the indexed address's low byte); `--sites` lists every access; no emulator, no specimen. |
| `menucheck.py` | Checks `session.py`'s `select_bar` and `select_row` against the running game (MOVE, CAST, picking a character, ENCAMP to SAVE GAME), each PASS or FAIL with a non-zero exit. |
| `openingscene.py` | Records every message a Curse or Silver Blades save shows after BEGIN ADVENTURING, and each character's experience before and after. |
| `outdoorsgrep.py` | Searches a title's disks for the word `OUTDOORS` in PETSCII and screen codes, the cheap first test of whether a title has a travel grid; a hit says where to look and proves nothing. |
| `overlay.py` | Reads a named game overlay at the addresses it runs at: `hex` dumps a range, `refs` finds every mention of an address, `dis` disassembles; `--base` defaults to `$0800`, since a PRG header cannot be believed. |
| `porcmd` | Sends one command to the running `session.py` driver and prints the reply; the port is `$POR_CMD_PORT`, or 6600 (a human's game) when unset, so a pooled session needs the port it printed exported. |
| `porlaunch.sh` | Launches VICE on its own X display with a disk autostarted, taking everything that makes an instance distinct from the environment so `tools/registry/instance.py` can give a slot its own; it kills nothing. |
| `pursecheck.py` | Sets a Curse or Silver Blades character's seven purses through the editor's own form and reads them off the game's character sheet, beside the `ENCUMBRANCE` the engine should recompute; `stage` and `run`; `docs/139-per-title-validation.md` A8. |
| `recordsweep.py` | Asks which of a title's files reference one byte of the character record, needing no load address; `--context` disassembles around each hit and `--indirect` censuses the `(pointer),Y` route. |
| `rosterbytecensus.py` | Counts one byte of the C64 roster block across every save disk in the player's directory as a histogram, or with `--equals-slot` how often it equals its own slot index; disks are opened read-only. |
| `rosterspellcount.py` | Compares a C64 roster block's per-level memorised-spell counters with the record's own list at `0x020` over every save disk given; needs no emulator; reads only. |
| `savecheck.py` | Boots a save disk in VICE and reads what the game shows: load result, status line, party panel, every character's sheet (`--view`), combat icons (`--icon`), area changes (`--route`), walks (`--walk`); `--resave` has the game write the party back. |
| `session.py` | Drives a Pool of Radiance session under VICE in one long-lived process (boot, copy protection, disk swapping, indoor and travel-grid walking, fights), since VICE serves one text-monitor connection per run; `docs/70-driving-the-game.md`. |
| `sheetexit.py` | Finds the one key (PETSCII `$5F`, the back arrow) that leaves a command bar in all three C64 titles: `keys` reads it out of the player's `LIBRARY`, `run` proves it by reading two characters' sheets in one boot. |
| `show.py` | Prints everything currently readable from a save disk, each field marked CONFIRMED, PROBABLE or GUESS by how far it is trusted. |
| `splatload.py` | Boots Pool of Radiance with a save disk and reads `$03F1`, the drive's own error number, to say whether the drive would open it; `--repair` closes a dangling directory entry in the staged copy only. |
| `statusdrive.py` | Makes the C64 engine write a character's status byte and reads it back: wounds one character to 1 hit point in the Slums ambush, saves and reads the roster off the game's disk; `--sheets`, `--stage` and `--panel` vary it. |
| `stepcheck.py` | Prints the step `Session.step_towards` picks at each of the six arena positions in `tests/gamedata.py` beside the answer each was measured to want; needs no emulator and no display. |
| `trainerscan.py` | Finds a Gold Box trainer's tables by the instruction that reads the character record: `--refs` prints each absolute operand landing in the record against `goldbox/layout.py`'s names, `--callers` walks back up to the caller. |
| `trainerspells.py` | Decodes what each C64 title's trainer does about spells from the `GEN` overlays and prints the spell ids a character of each level gains, with `--rows` or checked against `goldbox/spells.py` and `goldbox/levelup.py` with `--check`. |
| `traitask.py` | Logs every effect id the running C64 engine asks a character about, using VICE text-monitor tracepoints on `LIBRARY $3FE4`, `$402D` and `$403C`; stages items, trait ids, hit points or spells into a copy of a save; writes nothing to the player's disks. |
| `traitcross.py` | Shows which effect ids reach the C64's ten trait slots at record `0x0AD` for every character in a DOS save, by running the real conversion and printing a LOST column; `--all` sweeps `$WISH_SPECIMENS`, `--c64` reads a `.d64`. |
| `traitdrive.py` | Writes an effect id into a free trait slot of a copy of a C64 save, walks into the Slums ambush and counts executions of `LIBRARY $403C` with non-stopping checkpoints; `--stage SLOT:INDEX=ID`, `--save-game`. |
| `traitquery.py` | Censuses which effect ids the C64 engine asks a character's trait slots about, finding the predicate without a known run base; `--lists`, `--compare`, `--spells` and `--handlers` name ids; no emulator; `docs/171-c64-trait-slots.md`. |
| `traitsave.py` | Writes a trait through the editor's own buttons and reads it back from the running game: `write` builds the real `WishWindow` and reports the whole-disk byte diff, `boot` reads the ten slots live; opens no window; writes nothing to the player's disks. |
| `turndrive.py` | Watches the combat bar a C64 cleric is offered: stages `turn_power` into a copy of a save, walks into the Slums ambush and pairs the byte the engine read with row 24 at every command bar; `docs/178-turning-undead.md`. |
| `vicebankcheck.py` | Measures which monitor bank reads RAM under I/O by writing a marker into `$D000` through bank `ram` and reading it back through every bank; exits non-zero while the default bank cannot read RAM at the address. |
| `walkrun.py` | Builds series of saves unattended: boots, loads a save, walks a route in the game's own letters and saves at every step, recording a move that does not change the party position as a wall. |
| `wallsmap.py` | Reads the `.walls.bin` captures `tools/areas/wallpins.py` writes and prints one character per 128 bytes showing where `$ED50` agrees with `WALLS00`, with the three `WALLDEF` unpack destinations marked. |
| `whatis.py` | Says which game file, if any, a block of captured memory holds, by scoring every file on all eight sides at its own load address; a partial match shows a region built from two files; `--at-base` for a relocated region. |
