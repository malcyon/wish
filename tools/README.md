# tools

Developer scripts, not shipped — the emulator harness, the instance pool, the
disassembly and dump helpers, the code generators. Anything here may talk to a
live emulator, an X server or the player's own disks, which is exactly why none
of it is in `goldbox/`, `editor/` or `wish/`.

| file | purpose |
|---|---|
| `__init__.py` | Empty. |
| `amigadrive.py` | Types at an Amiga game running under WinUAE in the Windows VM, from Linux, and grabs the guest's screen. `winuae.ps1 key` presses one virtual key per call and every call is an ssh round trip through a scheduled task, so what this saves is the name-to-VK table and the waiting: `keys RET L S A V E SLASH RET` is the whole route into Pool of Radiance's `LOAD WHICH GAME:` picker. It takes no lane claim and releases none -- the claim `winuae.ps1` enforces has to outlive any one of these calls, so it is the caller's, and every call is refused without `--holder`. Nothing it does opens a window on the host. |
| `compare.py` | Loads every character specimen we have and reports, per record offset, how much the value varies — offsets that vary are candidate fields, and correlating that variation with attributes we already know is how the rest get identified. No emulator needed. |
| `d6502.py` | A small 6502 disassembler: given a raw overlay image, a load address, a start address and an instruction count, prints the addresses, bytes and mnemonics. Rescued from `work/rolls/` during the 2026-09-01 tidy rather than lost with the rest of that scratch — the research it supported (`docs/147-combat-rolls.md`) used it to turn `COMBAT` and `LIBRARY` into readable listings. |
| `diff.py` | Diffs two save disks and says what changed in game terms. The workhorse of the discovery phase: save, change exactly one thing in-game, save again, diff. Changed bytes resolve to slot plus record offset and are labelled with the layout field or flagged as an unknown region — the unknown hits are the interesting ones. |
| `dosbox.py` | A driven DOS Gold Box session: DOSBox on a private X display, unattended. Input is XTEST through `xdotool` aimed at a window nobody else owns (there is no window manager under a bare `Xvfb`, so `windowactivate` fails and the keystroke is lost); output is a 320x200 capture that is the VGA framebuffer pixel for pixel; ground truth is the save file DOS writes. The window is chosen by `_NET_WM_PID` and then proved to have pixels in it, a display something already answers on is refused rather than shared, and a screenshot of one flat colour is refused by name (#88). |
| `dosboxx.py` | The DOS debugger harness: `dosbox.py`'s session with the launch replaced by a DOSBox-X built `--enable-debug=heavy`, on a pty so its ncurses debugger has a terminal. Memory reads, `BPM` watchpoints, code breakpoints, registers, single-stepping and writes, over a log file — the DOS answer to VICE's binary monitor. Hides the four traps that cost an hour each: the 64K `MEMDUMPBIN` wrap, the spurious first `BPM` hit, the code breakpoint that logs nothing, and the 254-character command truncation. Displays :40-:47. |
| `drive.py` | Drives Pool of Radiance under VICE — the original binary-monitor client (still re-exported from `automap/vice.py`), key sending through XTEST on the nested display, and the surrounding discovery scaffolding. |
| `dump.py` | Annotated dump of a `.D64`, a save game or a `.chr` — disk directory, save summary, one character record, or a raw address range. |
| `fightrun.py` | Drives one fight from a player's save, unattended: boot a pool slot, load the save, walk until something ambushes the party, and hand every command bar to `Session.melee_turn`. Writes one JSON line per turn and prints the only summary that says whether a fight was fought — per character, the turns taken, how many had an enemy in contact, and how many of those ended with a blow struck. Three copies of this were written into `work/` for `#126`, `#127` and `#165` and thrown away with it; the data it produces still goes to `work/`, the tool does not. |
| `gendocs.py` | **Generates** `docs/20-character-record.md` from the field notes in `goldbox/layout.py`, so the documentation cannot drift from the code. Re-run after touching the layout. |
| `genimports.py` | Reads the module-level import edges inside one package out of the AST, and writes the dependency graph `docs/117-save-conversion.md` carries. **Generates** that graph rather than drawing it by hand, because the edge it exists to catch -- a codec importing another codec -- is exactly the one somebody adds without noticing. |
| `genicons.py` | **Generates** the platform icon files in `assets/` from `ui/appicon.py`, offscreen. Every size is rendered rather than scaled, because Windows picks the nearest entry and bilinearly scales it — a `.ico` holding only a 256 gives mush at the 16 px used in the title bar and Alt-Tab. `--check` asks whether `assets/` is in step. |
| `genitems.py` | **Generates** `docs/85-item-tables.md` by reading `ITEMNAMES` and `ITEMS` straight off a game disk, so the names carry no transcription errors and none of the data enters the repository. |
| `genlicenses.py` | **Generates** `THIRD_PARTY_LICENSES.md` from `ui/icons.py`, so the CC BY 3.0 attribution names exactly the game-icons.net glyphs that ship. `--check` fails if the committed file has drifted, which is what `tests/test_licenses.py` runs. |
| `genlevels.py` | **Generates** `docs/89-level-tables.md` from `goldbox/levels.py`. |
| `genmaps.py` | **Generates** `docs/88-map-files.md` from the GEO files on the game disks. Needs a set of disks — `POR_DISKS`, or a directory argument. |
| `genmemory.py` | **Generates** `docs/41-memory-regions.md` from `goldbox/memory.py`. |
| `genspells.py` | **Generates** `docs/86-spell-table.md` from `SPELLN00` on a game disk. |
| `gentemplates.py` | **Generates** `docs/87-item-templates.md` — every item record on the game disks, which are the records `wish` copies when a YAML entry names a `template`. |
| `genui.py` | Compiles `editor/character.ui` to `editor/ui_character.py`. The editor calls `ensure_current()` at startup so this is rarely run by hand; `--check` regenerates into memory and fails if the committed file differs, which is what CI wants. |
| `geomap.py` | Renders GEO map files as text floor plans, optionally with a save's party marked. `--find` is the anchor problem: given where the party stands but not which map, it reports every GEO where that square exists and the party is not inside a wall, narrowing 29 files to a handful. |
| `goldbox-a500.uae` | The WinUAE machine a Gold Box Amiga title boots on, in the Windows 11 VM: a stock A500 with Kickstart 1.3, both drives turbo, and `use_gui=no` so nothing waits for a human. Loaded with `winuae64.exe -f`; every line is overridable with `-s`, so one file covers every title. Carries the F11 binding for `SPC_ENTERDEBUGGER`, which is the only way into WinUAE's debugger on Windows — `use_debugger=true` cannot work there. Paths are the guest's; no game data. |
| `iconsheet.py` | Renders every icon the program ships at the sizes it is actually seen at, through the same painting code the map and the roster use. Exists because a table of icon *names* is how `hat-wizard` got chosen and how it turned out to read as a shark's fin at 13 pixels. |
| `inkcount.py` | Counts an icon's ink pixels and how many connected pieces it comes apart into, at the size the program actually draws it. The two numbers `docs/136-condition-badges.md` grades every condition badge by, and it reproduces all of them — the rig that produced them originally lived in a session and had to be rebuilt to add two rows. Ink says how much of the glyph survives (`invisible` was dropped at 55); pieces says whether it survives as one thing (`hat-wizard`'s brim stopped touching its cone and it read as a shark's fin). |
| `install-desktop.sh` | Installs `wish.desktop` and the icons under `$HOME` so a Linux desktop finds them. Needed because Wayland has no protocol for a client-supplied window icon — the compositor matches the app id against an installed desktop file, and with none it shows a generic gear. |
| `m68dis.py` | A 68000 disassembler that **refuses to guess**: a word it does not recognise prints as `dc.w $xxxx`, never as the nearest instruction that fits, because a made-up instruction in the middle of a string table is what gets believed and written into a document. Every field is checked before a mnemonic is emitted — an addressing mode the opcode cannot take, a 68020 index extension, a branch to an odd address. The last two are legal encodings on real silicon; refusing them is a judgement that **no assembler emits them**, so a word carrying one is data. Branches, `dbcc` and PC-relative operands print the address they reach, so a target needs no arithmetic. `--refs ADDR` walks a range a word at a time and reports every instruction pointing at one address, which is how the code that opens a `.pc` was found from the string alone. Reads a plain binary at file offsets; it does not parse AmigaDOS hunks, so give it `--offset`/`--length` inside the code hunk, and nothing outside that window is read — an instruction that would cross the end of it prints as `dc.w` rather than disassembling the next hunk. Verified against capstone 5.0.7 in `CS_MODE_BIG_ENDIAN | CS_MODE_M68K_000` over 100 385 instructions of the Amiga *Pools of Darkness* binary: no length disagreements, no operand disagreements, nothing capstone decoded that it refused — `docs/50-experiments.md` §"The 68000 disassembler". |
| `instance.py` | The VICE instance pool: six resources per slot (two monitor ports, a command port, an X display, a work directory and a private `vicerc`), held by one lease. The lease is an `fcntl.flock`, so the kernel frees a crashed run's slot with no cleanup script. Nothing here ever kills a process by name — teardown is `os.killpg` on the group *this slot* started. |
| `porcmd` | One-line shell client that sends a command to the running `session.py` driver on its command port and prints the reply. |
| `porlaunch.sh` | Launches VICE on its own X display with a disk autostarted. Everything that makes an instance distinct arrives through the environment (`POR_DISPLAY`, `POR_VICERC`, `MONFLAGS`, `PORFLAGS`, `POR_HEADLESS`) so `instance.py` can hand a slot its own copy of all of it. It kills nothing. |
| `porslot.py` | Copies an Amiga *Pool of Radiance* save slot into another slot on the same disk, which is the only caller of `goldbox.amiga.write_por_slot` outside the tests. The party is read back off the disk through `read_amiga_por` and `to_neutral`, so it crosses the same neutral record a converted party would and what cannot cross is printed. It is what put a slot list *written by our code* in front of the game's picker for `#109 (A save slot written onto an Amiga disk is not offered by the game's picker)`. The input image is opened read-only and `--out` is required. |
| `session.py` | A driven Pool of Radiance session — boot, copy protection, disk swapping, and driving a fight. The swap is the thing that makes automation possible and it is not obvious: the fliplist is unreachable from automation, but the *text* monitor has `attach`, and both monitor servers can run at once. One long-lived process, because VICE serves one text-monitor connection per run and closing it deafens every monitor. `in_combat`, `combat_state`, `combat_bar` and `fight` drive a battle; `docs/70-driving-the-game.md` has what row 24 means. |
| `shotstrip.py` | Photographs the automapper's roster column offscreen with a made-up set of party-wide spells running, and prints the icon row's tooltip, which a `grab()` does not draw. Exists because `shotwindow.py` runs with no emulator, so the party effects row is always empty in it — and because **no save this project holds carries a party-wide effect**, so the only way to look at that row at all is to write the effect table by hand. |
| `shotwindow.py` | Photographs the whole window offscreen at a chosen UI font size and width and writes a PNG, with the floor and the width actually drawn captioned on the picture and a marked line where a target width falls. Exists because #71 was decided by looking at three of these and not by reading `minimumSizeHint()`: a number cannot say whether a squeezed header draws on top of itself. `--font +6` measures here about like Windows' base font, so a Windows-sized layout can be seen without a Windows machine. Defaults to the synthetic widest party, so it runs with no game disks. |
| `show.py` | Prints everything currently readable from a save disk, with each field marked by how far it is trusted — CONFIRMED, PROBABLE or GUESS. |
| `toamiga.py` | Writes a C64 party out as Amiga *Pools of Darkness* `Save/NAME.pc` files, one per character, ready to drop into a disk 3 `Save` drawer. Goes through `goldbox/neutral.py`'s `NeutralCharacter`, so it reads any of the six C64 titles; what cannot cross is printed rather than dropped quietly. The C64 disk is opened read-only. |
| `walkrun.py` | Unattended corpus building: boot, load a save, walk a route in the game's own letters, and save at every step. A move that does not change the party position is a **wall**, which is the whole point. Tears everything down at the end and screenshots if anything goes wrong. |
| `winuae-send.ps1` | Types into WinUAE's debugger console from a script and reads the console back as text: `AttachConsole` to the emulator, `WriteConsoleInput` for the commands, `ReadConsoleOutputCharacter` for the replies. Runs on the guest, in session 1 — consoles are per-session and an SSH shell is in session 0. The read path a `WinuaeTarget` rests on is `S <file> <addr> <n>` here plus an `scp`. Every path out ends `--- exit N token=...`, carrying the caller's own token, so the caller can tell "still working" from "died before it started" and cannot read an earlier call's log as this one's; a failed write falls through to the readback rather than losing the debugger's own account of what went wrong; and the arguments are checked before a console is touched, because an unguarded `-File` killed the process where it stood and left no verdict at all. |
| `winuae-lanecheck.ps1` | Proves that one driver of WinUAE cannot destroy another's run. Runs on the Windows guest against whichever copy of `winuae.ps1` it is pointed at, so the version before `#116 (Two agents cannot share the WinUAE VM, and neither of them can tell)` can be watched to fail: a second driver's `stop` ended the first's emulator 3 of 3 rounds, its `key` pressed into the first's game 3 of 3, its `start` was handed the first's emulator as its own success 7 of 9, and six simultaneous `claim`s granted all six callers the lane — against none of any of those afterwards. The hijack round says whether it *actually raced*, because it needs two calls to overlap inside the second WinUAE takes to become a process, and a round that never reached that condition would otherwise read as a pass; it fails outright when no round raced. Also checks the paths that must keep working — the holder's own `start`, `key`, `send` and `stop`, and that `start` passes its WinUAE arguments through untouched, which is the thing a new parameter on the driver silently breaks. Resets the lane between rounds through the scheduled task, never by killing a process by name. Its `reclaim` round storms a holder re-asserting its own lane while three others claim, with the callers jittered so they do not fall into lock-step and read only the phase where the file is there — the fault it was written for is a two-millisecond window that 198 unjittered attempts never once hit. That round asserts both halves — nobody else let in, and the holder still able to re-assert its own lane — because asking only the first passed four times against a build whose every re-claim failed: a holder that never lets go lets nobody in. |
| `winuae.ps1` | Starts, stops, raises and drives WinUAE on the Windows guest through `winvm ssh`. Every action goes through a scheduled task with an Interactive principal, because `winvm ssh` lands in session 0 and the VM's screen is session 1: a GUI process started from session 0 is invisible to `winvm shot` and cannot be focused from there. `key 7A` presses F11 into the emulator, which is what opens the debugger, and `roms` points WinUAE's ROM database at `C:\Amiga\Kickstarts` and rescans it without a GUI, so a person who opens the emulator is not told there are no Kickstarts. Every action reports `ok` or `fail` and exits accordingly: an Interactive task started with nobody logged on at the console runs nothing and says nothing, and a task started while its own last instance is still alive is ignored outright and hands the caller that instance's receipt — which is how a whole run can report success and produce empty dumps. So each call stops the task before starting it and matches a token of its own in the receipt, `start` refuses to run a second emulator over the first, and `clean` refuses while one is running, since unregistering the task would strand it where the only way out is a kill by name. Two emulators are refused rather than guessed between: `roms` launches its own for the scan, so it refuses over a live one, and `front`, `key` and `send` refuse when they find more than one and name both pids. The VM is single-tenant and now says so: `claim -Holder <id>` refuses a second holder, `start`, `stop`, `key`, `send`, `front` and `roms` refuse a caller who is not the holder, `start` checks that the emulator it found is running the command line this call passed and writes a receipt naming the pid, and `stop` refuses a `winuae64` that receipt does not describe — because with one task and one process name a second agent does not get a second emulator, it gets yours, and before this its `stop` ended somebody else's session three times in one night. `tools/winuae-lanecheck.ps1` is the proof. The claim is an atomic file create plus a read-back of the caller's own token, not a read-then-write: six claims arriving together used to grant the lane to all six. Every refusal carries the `-Override` line that clears it, because a lane whose holder has died is otherwise a lock nothing tells you how to open. A holder re-asserting a lane it already holds writes nothing at all, because deleting the file first left it reading free for long enough that somebody else could take it without asking. |
| `wish.py` | The implementation of `wish export` and `wish import` — a save disk to YAML and back. No longer a program of its own; `wish/__main__.py` dispatches to it. An existing disk is never modified: `import` always writes a new one. |
