# tools

Developer scripts, but the package ships anyway — the emulator harness, the
instance pool, the disassembly and dump helpers, the code generators, and
`tools.wish`/`tools.genui`, which `wish` reaches into at runtime
(`tools.wish` is named explicitly in `wish.spec`'s `hiddenimports`, since it
is the body of the `wish export`/`wish import` subcommands and no static scan
sees the import that reaches it; `tools.genui` is imported directly by
`wish/__main__.py`). Anything here may talk to a live emulator, an X server or
the player's own disks, which is exactly why none of it is in `goldbox/`,
`editor/` or `wish/`.

**The 95 Python files under `work/` were swept on 2026-09-02** for
`#181 (Ninety-five Python files sit under work/, and some of them are tools
nobody can find)`, asking of each whether somebody would otherwise write it
again. Nine said yes, and they became the six tools `combatshot.py`,
`d6502check.py`, `m68discheck.py`, `overlay.py`, `rostercard.py` and
`whatis.py` below -- six rather than nine because several files in one
directory were one tool between them. Seven of the nine were moved and the
originals deleted; two were copied instead, because a dozen sibling scripts
import them and deleting them would break the record of the runs that used
them.

The other 86 are a run's output: an emulator driver edited into its own
successor, a measurement of one window, a copy of a package file taken before
a change. They stayed where they are, and moving them would have cost this
table, which is the only thing that makes a tool here findable.

**Those 86 were read again on 2026-09-03** for
`#199 (Promote the tools stranded under work/ into tools/, where they can be
found)`, which was filed without knowing
`#181 (Ninety-five Python files sit under work/, and some of them are tools
nobody can find)` had run. Re-reading a sweep from
the day before is not usually worth anybody's time, and this one was: six more
said yes -- `bigfont.py`, `combatdiag.py`, `libslots.py`, `menucheck.py`,
`monitorchain.py` and `wallsmap.py` -- from seven files, and every one of them
had been sorted into the 86 as "an issue's measurement". They are not. Each
one **checks a tool that ships**, or reads what one writes, and the reason the
first pass missed them is that they are named after the issue that provoked
them rather than after the thing they exercise.

So the sort that matters is not run-driver against question-answerer, which is
what the filenames say. It is *what does this point at* -- a thing in `tools/`
or in the packages, which makes it a tool, or one row of one issue's evidence,
which does not. The 82 left behind are listed on
`#199 (Promote the tools stranded under work/ into tools/, where they can be
found)`'s closing comment so a
third sweep does not read them a third time; anything added to `work/` after
2026-09-03 has been read by nobody.
