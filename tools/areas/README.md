# areas

Scripts for a game's areas: the area tables, the scripts that run in them, their maps, and the exits and fast-travel routes between them.

| file | purpose |
|---|---|
| `areatable.py` | Builds a title's area table out of its own `ECL` scripts: one row per script with the disk side that carries it, the `GEO`s it loads and the square it puts an arriving party on. Opcode tables and script load address come from the title's own files through `newecl.py`; disk and square are propagated over each script's control-flow graph, so a `NEWECL` reports only what is true on every path that reaches it. `--check` re-derives a title's table and diffs it against `goldbox/areas.py` field by field. Prints a string operand as its length, never as text. |
| `ecl6derefs.py` | Lists every reference to `$6DE0`-`$6DEF` in Pool of Radiance's thirty area scripts, by the control-flow walk and by a raw byte scan that marks anything NOT WALKED, plus every SAVETABLE base and index that could reach `$6DE6`. Reads the player's C64 disks through `eclcensus.py`; writes nothing. |
| `eclcensus.py` | Censuses where a title's area scripts keep their variables, on the C64 and on DOS separately because the ports load the save at different addresses. `--compare` diffs the two ports' bytes, `--range` prints one row per address, `--sites` every statement naming one, `--loadfiles` runs the control-flow walk and a raw byte-pattern scan so the two can disagree. `eclflags.py` is the fuller reading and is Pool of Radiance's alone. Prints no string of the game's as text. |
| `eclexitkinds.py` | Says how each exit in the area scripts is reached -- `edge`, `square`, `edge+square`, `square-via-entry0`, `entry1-unconditional` or `entryN` -- with the id and the `GEO` squares carrying it, and the statements on the route a player would notice: a menu, printed text, a `LOADCHAR`, a quest flag, a position write. Regenerated from the disks through `eclwalk.py`; prints no string of the game's as text. |
| `eclflags.py` | Lists every reference the thirty area scripts make to the quest-flag page `$4A00`-`$4AF8`, classified into reads and writes and keyed by address, using `eclwalk.py` and the instruction set's own destination operands. `sites 4A81` prints every instruction that touches one address; `doc` regenerates `docs/151-quest-flags.md` whole. Prints no string as text: the English in its last column is joined out of `goldbox/commissions.py`. |
| `ecllist.py` | Reads one area script: a run of statements from any offset, the 6502 handler behind an ECL opcode, and which `COMBAT` statements a given saved game can reach. `--at` takes the address a script runs at or its offset in the file, `--raw` dumps bytes, `--handler` disassembles an opcode's handler found through `newecl.py`, and `--combat --save` walks every arm of an entry's `ONGOTO` with a real `SAVEDBASH` in hand, branching both ways only where a value is unknown. Prints no string of the game's as text. |
| `eclnpc.py` | Lists every reached `ADDNPC` in Pool of Radiance's thirty area scripts with the `MON` record each one joins and the control-flow path in front of it. `census` walks each script through `eclwalk.py`'s `Script` class; `gaps` checks that no byte the walk never reaches decodes as an `ADDNPC`; `gate ECL0B 9FEB` walks backward from a statement and prints every block that reaches it. It prints the `MON` names, which are the game's own words, so its output belongs in a terminal and not in `docs/`, a README, a commit message or an issue. |
| `ecltext.py` | Decodes an area script's packed strings, so a screen capture can be matched to the statement that printed it, using the string decoder in the title's own `DUNGEON`. `--text` and `--find` print the game's own prose, so their output must not reach `docs/`, a README, a commit message or an issue; without `--text` it prints offsets and lengths only, which is safe anywhere. |
| `eclwalk.py` | Reads an area script statement by statement and prints, per exit, exactly what a fast travel skips. Opcode handler tables, operand counts and operand forms all come out of `DUNGEON` at run time, and each script is walked from its five entry addresses following `GOTO`, `GOSUB`, `ONGOTO`, `ONGOSUB` and both arms of every `IF`. Prints a string operand as its length and never as text. See `docs/150-departing-prologues.md`. |
| `exitreentry.py` | Runs an exit's own handler from outside the game: teleports the party on to the exit square and re-enters `DUNGEON` where a step would have arrived (`$0957` after a landed step, or `$0A4C` then `$0978` for the forward key off a map edge), with the stack rebuilt from the depth `$03BF` records. Phases measure the idle stack at the command bar and in MOVE mode, the `NO` and `YES` answers at the Kobold Caves' exit, the second hop back indoors, and an edge exit from New Phlan. Captures go to the temp directory. |
| `exitroute.py` | Prints every statement on the route to one exit, from the entry `DUNGEON` dispatches through down to the `NEWECL`, marking what a player would notice: a menu, printed text, a `LOADCHAR`, a quest flag, a position write, a fight. `eclexitkinds.py` counts those features; this shows the route they came from. |
| `fasttravelpcwait.py` | Measures how long the program counter stays outside Fast Travel's windows, idle at 20 ms and 5 ms sampling and while the party walks. Claims a pool slot, stages the Pool disks and a save (`--save`, default `PORSAVE11.D64`), boots and drives the game; writes `wait.json` under `--out`. |
| `fasttravelrun.py` | Drives the shipped `automap.actions.FastTravel().run()` through a real `automap.target.ViceTarget` on a pool slot: boots `npc_party.d64`, warps from the Kobold Caves (area 13) to the East Window (area 27), answers the handler's `YES`/`NO` prompt on row 24, and checks that Princess Fatima was dropped from the roster as walking out drops her. With `WISH_EXPERIMENTAL_TWO_HOP_FAST_TRAVEL` set and `--to-area 0` it drives the two-hop trip, times the second hop, saves four screenshots and, after a pass, walks the party and opens a character sheet. `--from-area`, `--to-area` and `--member` generalise the check; `--disks` and `--out` fall back to `$POR_DISKS` then `automap.paths.find_disks()`. The pool owns the emulator lifecycle and tears it down on every exit path. |
| `geomap.py` | Renders GEO map files as text maps, optionally with a save's party marked. `--find` takes where the party stands but not which map, and reports every GEO where that square exists and the party is not inside a wall. |
| `georesident.py` | Measures how far the resident map block at `$0400` drifts from its `GEO` disk copy in a driven *Pool of Radiance* game. Boots, loads a save and, for every step of a `--route`, asks the shipped `ResidentGeo.verdict` what the block is, records the distance to every map, and counts loads and stores into `$0400`-`$07FF` with two VICE checkpoints. Writes `run.jsonl` and one screenshot per step into `--out`; never writes the player's disks. |
| `geowalk.py` | Walks a driven session to a square, routing breadth-first over the area's own `GEO` so it never asks the game to walk through a wall, and resuming when a scripted square interrupts with a message. |
| `loadfiles.py` | Lists every `LOADFILES` and `LOADPIECES` in a script with its immediate operands, to show what an area loads and gives back. A byte-pattern scan that needs no `DUNGEON`; `eclwalk.py` is the fuller reading and knows what a statement is. |
| `newecl.py` | Finds a title's `NEWECL` handler and everything else a fast travel needs -- the tail to jump to, the key-wait window, the key fetcher, the mode flag, the disk byte, the cache slot and the two save-relative writes -- by reading its own `DUNGEON`, `LINKER` and `LIBRARY`, with no address taken from a PRG header. Finds the script VM by its self-modifying dispatch and compares the handler with Pool of Radiance's instruction for instruction, so a title whose handler differs says so instead of returning a plausible address. |
| `postcom6dereads.py` | Lists every read of `$6DE2`, `$6DE3`, `$6DE6`, `$6DC6` and `$6DE1` in Pool of Radiance's `POST.COM`, with eight 6502 instructions from each: the engine side of ECL00's tavern-brawl writes. Reads the player's C64 disks; writes nothing. |
| `reentrypoints.py` | Checks the five re-entry addresses `exitreentry.py` uses against the player's own `DUNGEON`, with no emulator: derives `saved_sp` and `main_loop_return` from the bytes (`NEWECL`'s tail is `LDX <saved_sp> / TXS / JMP <main loop>`), and checks `after_step` (which must call the committed `redraw`), `forward_key`, the main loop's `TSX / STX <saved_sp>` and the wall test. Seven checks; exits 1 if any fails. |
| `wallpins.py` | Pins two wall pieces via `$49E7`-`$49E9` in Valhingen Graveyard and watches the next area draw them: three arrivals at Podol Plaza's own square with the party held constant, warped in from the Slums, warped out of the graveyard with the fix's `$49E7` write dropped, and with the whole of `newecl_writes`. The faulty run is built by removing one entry from the write list here, never by editing `automap/actions.py`. `--plan walkin` steps west off the graveyard's edge to watch the game clear the pins itself, then tries the eight compass digits to walk back in. Captures go to the temp directory. |
| `windowsquare.py` | Warps to each wilderness window and tries to walk off the square `goldbox/areas.py` ships, since passability lives in each window's own impassable-terrain table. `$49C3`/`$49C4` are seeded (0, 0) before every warp, the warp goes through the shipped `FastTravel.apply`, and each of the eight compass digits is pressed with the party put back on the arrival square. Answers the boat menu and presses again before calling a direction blocked, because both boat landings re-open TAKE BOAT / STAY each time. Captures go to `--out`, by default the tool's scratch directory. |
