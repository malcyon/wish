# goldbox

The game's formats, decoded — character records, save games, maps, items, spells — with no Qt, no emulator and no transport, so everything here is bytes in and bytes out.

| file | purpose |
|---|---|
| `__init__.py` | Empty. |
| `amiga_adf.py` | The Amiga floppy filesystem (OFS), read and written: allocates blocks from the bitmap counting down from the top of the disk (a cracked release reads blocks the bitmap calls free), builds file headers, threads them into the parent drawer's hash chain and fixes every checksum, with `make_dir` for tests, `restore` to roll a whole image back to a snapshot, and `walk_dirs` so `verify()` reaches each drawer's own header block. |
| `amiga_dax.py` | The Amiga `.dax` container, a big-endian block index over ByteKiller-packed blocks and a different format from the DOS `.DAX` in `dos_savegame.py`: `index`, `block` and `blocks` read it, `unpack` is the depacker transcribed from the game's own routine and refuses a block whose trailer length or checksum does not add up, and a conversion needs it because the Amiga keeps every area's script in one `ecl.dax` on disk 2. |
| `amiga_later.py` | The Amiga Curse of the Azure Bonds and Secret of the Silver Blades codec: `AmigaCharacter` and `AmigaItem` (Curse's 66-byte item node) read records through their `AmigaDeltas` row in `amiga_port.py`, `read_amiga_guy` reads a `.guy` pregen, `party_in_savegame` finds a party in a saved game by signature, `to_neutral_later` and `write_later` are the reader and writer, and `get` raises for a field inside one of the three Curse windows that hold an unlocated insertion rather than return a byte from the wrong side of it. |
| `amiga_pod.py` | Amiga Pools of Darkness `Save/NAME.pc` character files, big-endian: `pod_to_neutral` reads and `write_pod`/`to_pc` write, the record holds base values only because the game rederives THAC0, encumbrance and movement on load, the `POD_WRITE_*` tables say what the writer does with each neutral field, and no other title's module is imported. |
| `amiga_por.py` | Amiga Pool of Radiance character, item and effect files, read through a shift map onto the DOS field table in `dos_port.py` so the two cannot drift: `to_neutral` re-cuts the 288-byte record into the 285-byte DOS one for `dos_codec.to_neutral` and names every `.spc` effect the neutral record cannot hold, `write_por` runs the transposition backwards over `dos_codec.write`, `write_por_slot` writes a whole slot (six characters, their item and effect files, the saved game and the ten-byte `SAVE/save` the picker reads, indexed by slot letter with `A` at byte 0) all or nothing with a rollback and refuses a slot it cannot list, and Curse or Silver Blades records go to `amiga_later.py` through a deferred import. |
| `amiga_port.py` | The Amiga port of the Gold Box character record, with no code that reads one: `AmigaDeltas` is one title's record as a shift map onto that title's `dos_port.py` field table (never a second copy of it), `CURSE_DELTAS` and `SILVER_BLADES_DELTAS` are the two rows, and it holds the sizes the Amiga titles agree on (a 16-byte NUL-padded name, a ten-byte effect node, the three insertions in the 66- and 70-byte item nodes); it imports `dos_port.py` and nothing else here. |
| `amiga_shared.py` | What more than one Amiga title's codec needs and no title fact: the two big-endian byte readers, the enum-table helper, the tuples naming neutral fields every port spells the same way, and the registries that see all titles (`deltas_for`, which names a title from a record's length, and `CONVERTS`/`WRITES`); the title modules import it and it imports none of them at module level. |
| `amiga_savegame.py` | All three Amiga saved-game containers: reads embedded or filename parties and world state, builds every byte from a source save without a template, and formats the fresh OFS disk that carries the result. Pool of Radiance slot and disk operations live here, and so does the Pools of Darkness container map (`pod_parse`, `pod_rebuild`, `pod_from_amiga`); its character, item and effect conversion remains in `amiga_por.py`. |
| `areas.py` | The single source of truth for the thirty Pool of Radiance areas, keyed by area id rather than by map file (`ECL0C` does not exist and four areas never put a `GEO` on the screen), which gives thirty areas and twenty-nine maps as `docs/88-map-files.md` inventories. |
| `assets.py` | The one resolver for files the program reads at run time from the checkout, such as the artist's SVGs: `asset_path` finds them under the checkout, or under `sys._MEIPASS` in a PyInstaller build, where `wish.spec`'s `datas` unpacks them, and `tests/wish/test_assets.py` fails the build if any other module builds a path to the checkout root. |
| `backstab.py` | A thief's backstab damage multiplier computed from a neutral record by each title's and port's own arithmetic, fourteen rules in `RULES` keyed by title and port, with the level and multiplier caps, the sum-or-larger treatment of a regained former thief level, and None where the engine finds no thief; the to-hit adjustment is not computed. See `docs/225-the-dos-backstab-multiplier.md`. |
| `c64_codec.py` | The C64 codec: a `NeutralCharacter` becomes 580 C64 bytes and back again, every byte written being sourced, computed by a named rule or a documented constant, and the reader taking the roster block and the item page separately because a save slot holds only 256 of the 580; `C64Deltas` is the ways one title's record departs from Pool of Radiance's, and `deltas_for` resolves the title's row. |
| `c64_port.py` | The C64 registry: the six titles in order, `BY_KEY`, `BY_TITLE`, `BY_SAVE_FILE`, and `detect`, which turns a disk in a drive into a title; the rows are `c64_save.py`'s `C64Container` (`Game` is that class under its old name), live addresses belong to `automap/c64.py` because `goldbox` may not import `automap`, and Pool of Radiance and Curse stay first because `wish/preferences.py` takes the first two. |
| `c64_save.py` | One C64 title's saved game, whole: its file name, size and load address, which pages are characters, items, names, `ANIMATE00`'s picture buffer and the roster, which header bytes are computed and which are written as zero, and whether the loaded-files cache needs bit 7 set; every offset is a payload offset (the image moved by `$200` between Pool of Radiance and every later title with nothing inside it moving), three of the six `C64Container` rows have no payload map so `container_for` refuses them, and `rules` is the `Title` whose C64 release the row is. |
| `classcode.py` | The class code byte's shared table and repair rule, used by `c64_codec.py`'s reader and `dos_codec.py`'s writer, which cannot import each other: `code_for` says what a record's own classes name and `repair` says what should replace a stored code that disagrees, as Curse of the Azure Bonds' own trainer leaves it stale (`docs/187-the-class-code-byte.md`). |
| `commissions.py` | The City Council's reward ledger, offer board and summons, read out of the 224 persistent flag bytes at `$4A20`, and the side quests an area script keeps for itself; no transport, so it works from a save file or a live read alike. |
| `d64.py` | Commodore 1541 `.D64` reader and writer that can build a disk from nothing: `blank()` formats a 35-track image with a valid BAM and an empty directory, and `write_file` allocates blocks, writes the sector chain and links a directory entry, growing the directory chain past eight entries; a file is never grown or replaced (`write_file_inplace` rewrites one over its existing chain at the same block count) and nothing scratches a file, so no block is ever freed. |
| `derive.py` | Recomputes armour class, THAC0 and the damage bonus from the AD&D rules so a value the game cached and never refreshed can be reported as stale; writes nothing. |
| `dos_codec.py` | The DOS Gold Box codec. It reads all four titles, converts Pool of Radiance through neutral records, and writes the record, item, effect and saved-game files. `DosCharacter.deltas` holds the per-title record differences; `write_deltas` resolves the target title. |
| `dos_port.py` | The DOS character record as the same declarative `Field` / `Confidence` table `layout.py` uses: Pool of Radiance's 285 bytes, and the other three titles as one `DosDeltas` row each (width overrides against that table, from which `layout_for` accumulates the offsets), where a wrong width stops the record adding up to its own size and raises at import; `dos_codec.py` reads it and the player's own files are never written to. |
| `dos_savegame.py` | The DOS `SAVGAM?.DAT` map: container rows, accessors for the party, clock, variables, wallset and script buffer, writers that point a save at another title or slot, and the `.DAX` container reader; `DosContainer` and `container_for` resolve the saved-game layout by title or size. |
| `effects.py` | The 64-slot active-effect arrays at `SAVEDGAME0` `$4900`, owned by a character, a monster or the party and distinct from the ten trait slots at record `0x0AD`, plus `load_effect_table`, ECL65's 67-record spell-effect table relocated to `$9900`, read off a game disk for a new effect's duration, and `RunningEffect`, the neutral row for a spell still counting down. |
| `encoding.py` | The three biased fields in one place — THAC0 and armour class stored as `60 - value`, the armour bonus as `48 + value` — as functions so no caller subtracts by hand. |
| `geo.py` | The GEO map format: four 256-byte planes over a 16x16 grid, with wall art and passability as two independent fields that must not be conflated. |
| `iconparts.py` | The icons the game can actually make — a weapon and a head, chosen in pairs by size — read out of the `SPELLE64` / `SPELLN64` icon editor: `default_icon()` composes the one the game's own character creation writes, and `recognise()` runs the model backwards for a conversion out of the C64, naming the weapon exactly and every candidate for the head, since some large heads are another head with hair added in two cells a weapon can cover. |
| `icons.py` | The eight 36-byte combat icons at `$4BE0` in `SAVEDGAME0`: 18 screen codes then 18 colours. |
| `items.py` | Inventory — the sixteen 16-byte item records per character at `$5900 + slot * $100`, and the word table the game assembles item names from; weights are in tenths of a pound. |
| `layout.py` | The 580-byte C64 character record as a declarative table of fields, each with a confidence grade; nothing else in the project may hard-code an offset, bytes no entry claims become UNKNOWN regions at import time, and its field notes are generated into `docs/20-character-record.md` by `tools/generate/gendocs.py`. |
| `levels.py` | Experience thresholds, saving throws, turning and spell progression, per title, read off the player's own disks and cross-checked against AD&D 1st edition rather than taken from either alone. |
| `levelup.py` | Reproduces, field by field, what the training hall writes at a level-up, with each step traced to the `GEN` routine that performs it. |
| `memory.py` | The game's memory map outside a character record — party header, loader caches, combat tables — as a descriptive table with confidences, generating `docs/41-memory-regions.md` through `tools/generate/genmemory.py`. |
| `monster.py` | The two attack forms and the experience award, read off any 580-byte record (a goblin and a level-1 fighter are the same structure), from `0x0D9`–`0x0E0` and never the working copies at `0x111`. |
| `neutral.py` | The port-neutral character record every conversion passes through, where each value carries its provenance and not just a number, plus the `Writer` every writer inherits the take-refuse-report protocol from. |
| `world_state.py` | `WorldState` — the saved game around the party (place, clock, wallset, quest flags, per-script scratch) in the ECL address space all three ports share, with no per-field grade because all three engines' save routines name every address identically; `from_c64`, `from_dos` and `from_amiga` are the readers; `PodWorldState` and `pod_from_dos` are Pools of Darkness' own, over its byte-wide variable array, and `amiga_savegame.pod_from_amiga` fills the same class from the Amiga slot. |
| `petscii.py` | C64 text, keeping the two string conventions apart: NUL-padded ASCII inside a character record, shifted-space-padded PETSCII in a 1541 directory entry. |
| `portraits.py` | The character sheet's portrait and the one enumeration the C64 and DOS ports share — fourteen heads and twelve bodies with the same art ids on both sides — where the C64 record stores the id and DOS the menu position, so a conversion needs the menu: `tables_from_dos` finds it in `START.EXE` and `tables_from_c64` in `GEN` on `POOL3`, Pool of Radiance's twenty-six numbers are stored in `POOL_OF_RADIANCE_MENU` so a conversion needs no disk for them (the readers stay as the check that they are still right), and Curse and Silver Blades draw no sheet portrait and need none. |
| `record.py` | `CharacterRecord` — bytes in, bytes out, with every field read and written through `layout.py`, so a decode/encode cycle is byte-exact by construction and the bytes of unknown meaning can never be dropped or zeroed in passing. |
| `rewrite.py` | Puts an edited character back into the DOS or Amiga save it came from without converting the fields nobody touched: the port's own writer renders the character as read and as edited and only the spans the two renderings disagree about are copied onto the engine's bytes, so a save with no edit in it is byte-identical and an untouched field keeps the engine's answer -- [223-the-differential-rewrite.md](../docs/223-the-differential-rewrite.md) is the census of where the two differ. |
| `savegame.py` | The save container in both its forms: Pool of Radiance's two files (`SAVEDGAME0`, a raw `$4900`–`$64FF` memory image, plus `SAVEDGAME1`), and the single 7426-byte file every later title writes. |
| `spells.py` | The spell name table per title, and what the packed list of spell ids at record offset `0x020` means; the names live on the game disk and where they live is the one thing that does not transfer between titles. |
| `titles.py` | A Gold Box title's own rules — races, classes — apart from any platform it shipped on: `Title`, seven rows including Pools of Darkness, which has no C64 port and so no row in `c64_port.py`; `race_table`, `class_table` and `classes_to_names` are duck-typed on `.key` as `spells.for_game` is, so a `Title`, a `goldbox.c64_port.Game`, a bare key or `None` all work. |
| `strength.py` | Recomputes PARTYSTRENGTH, the number twelve area scripts size random encounters from; nothing stores it, so this walks the roster the way `DUNGEON $1BE8` does, using the biased THAC0 and armour class bytes as stored and not as decoded. |
| `traits.py` | The ten trait slots at `0x0AD` — racial abilities, monster specials, item powers — as a 1–139 namespace per title with 66 entries confirmed against the player's own disks; Pool of Radiance's table is the DOS port's too and Curse shares it, while Silver Blades reassigned the numbers and has its own, smaller, table. |
| `world.py` | `SQRDATA0n`, the overland travel map — the combat square engine's structure (`automap/combat.py`) applied to the wilderness: the 18x36 grid, the 120 tile glyphs, and the three files stitched at world x 15 and 28 (`x + 13 * window_index`); `passable()` and `site_at()` are named but not implemented, because the site and impassable-terrain tables live in `ECL19`/`ECL1A`/`ECL1B`'s bytecode (`docs/115-review-the-scripts.md`). |
| `yaml_io.py` | The YAML codec: writes a `NeutralCharacter` out as data and imports a document back into a save, losslessly; only understood fields are editable, and the header, the roster tail and the unidentified majority of each record are preserved byte for byte. |
