# automap

The live automapper: everything that knows about a running machine — the VICE client, the map state, the rendering geometry, the window — kept apart so `editor/` never talks to an emulator and the decoding half of each pair stays Qt-free and testable headless.

| file | purpose |
|---|---|
| `__init__.py` | Package docstring only: why the live code is separate from `goldbox/` and `editor/`. |
| `actionbar.py` | The row of buttons under the map: each carries one action, is disabled with the reason in its tooltip when the mode flag forbids it, asks first where the action is irreversible, and reports to the messages panel rather than a pop-up so the map stays usable. |
| `actions.py` | The engine behind those buttons: an action takes a `Target`, decides whether it is legal, and either writes or says why not; no Qt, legality is re-checked at `apply` time and gated on `C64Machine.mode_flag` (the byte `LINKER` dispatches on) and never on the screen, a title whose loader has not been read has no flag so every action refuses, and nothing here writes to a disk. |
| `amiga.py` | A running Amiga read through WinUAE's own debugger, as a `Target`: one `ssh` round trip writes a debugger batch, presses F11, injects it and prints the dumped bytes back as base64, because there is no socket; it supplies its own `fix` (the engine's live x, y and facing), dereferences the pointer the game's map routines use so `ResidentGeo` gets an address, measures every address at run time by searching memory for a string the title's data hunk carries because AmigaDOS relocates on every load, refuses a title with no `MACHINES` row, and reads the title's whole map library off the player's own Amiga disk (`GEO.GLB`, a `GLIB` container, keyed `GEO{id:02X}` as the C64's filename for the same area is) so an Amiga party's map is drawn on the same sheet and reads the same notes. |
| `area.py` | Which GEO map the party is standing on, answered two ways: `ResidentGeo` matches the 1024 bytes at `$0400` against the disk copies, which is exact and moves into a new area as the load finishes (at `$0400` on a C64, and wherever `address_now()` says on a machine whose loader allocates the buffer, such as the Amiga), and `Fingerprint` needs no addresses and stays wired underneath as a contradiction check. |
| `busguard.py` | Declines to read a C64 Ultimate while its drive is mid-transfer: one byte of `$DD00` is read before each tick and the tick is skipped when the serial bus is busy, because every read over the Ultimate's interface stops the 6510 and a stop inside a disk load hangs the machine; it is a workaround, not a fix (it can race a load that starts after the guard byte), a busy-looking value that holds still for three readings is a rest state (the game's fastloader rests with the drive holding DATA), it holds the size ceiling every tick read is tested against, and a backend opts in with `halts_on_read = True`, which VICE never does. |
| `c64.py` | A running C64 as the addresses one title keeps things at — `C64Machine`, one frozen row per title, mirroring `amiga.py`'s `AmigaMachine` — where a title with no measurement is refused rather than handed another game's numbers: it holds `$C04B`, the engine's own party square, and `LINKER`'s dispatch byte (`$6E11` in Pool of Radiance, `$7F11` in Curse and Silver Blades, None in the three Krynn-era titles so every action refuses there), and raises each save-image region to a live address with the offset taken from `goldbox.c64_save.Container` so the file and the machine cannot drift. |
| `combat.py` | What the machine holds while a battle runs, and where to draw it; no Qt, gated on `$6E11 == 2` because outside combat `$8B00` is a graphics buffer and an ungated reader stacks every combatant at (0,0), with the battlefield read from the `SQRPACI<nn>` parameter block and never assumed. |
| `combatlog.py` | Keeps the combat messages the game throws away: the game prints who hit whom, holds it in a software delay loop and paints over it, so on an emulator faster than a 1 MHz 6510 the line is gone before it can be read; this folds screen text into messages and the window paints them. |
| `config.py` | Settings that survive closing the window, as small hand-editable JSON; an unreadable or half-written file counts as no settings yet rather than as an error. |
| `fasttravel.py` | Where each title keeps the bytes a fast travel writes, one row per game and None for a title nobody has read, with every address read out of that title's own overlays because `NEWECL` sits at a different address in each (`tests/test_newecl.py` re-derives the table off the player's disks), and a title with no row refused rather than given Pool of Radiance's numbers. |
| `gamedisks.py` | The registry of where the game disks and saves are for the tests and tools: this machine's `gamedisks.yaml` (gitignored, copied from `gamedisks.yaml.example`) with environment variables winning, which `paths.py` consults for a title's candidates; run as `python -m automap.gamedisks` it prints each entry's layer, path and whether it exists. |
| `live.py` | What the running game holds right now, as data; no Qt, covers the whole tab in two reads because the cost of reading a live machine is the round trip and not the bytes, and every address comes from the `goldbox.c64_port.Game` descriptor so a new title costs a table row. |
| `maps.py` | Finding and loading the `GEO` map files off the player's own disks — `default_disks`, `load_maps`, `load_maps_titled` and `forget`, which `wish/window.py` and `wish/__main__.py` import. |
| `noteeditor.py` | Adding, editing and deleting a note without stopping playing: a popover at the square rather than a modal dialog, and clicking a square that already has a note opens that note with a Delete beside it. |
| `noteeditor.ui` | The Qt Designer form for the note popover. Compiled to `ui_noteeditor.py` by `tools/generate/genui.py`. |
| `notes.py` | Typed notes on a square; no Qt. A note is a kind plus a few words (the kind carries an icon visible from across the map, the words are the tooltip), `type` is stored as a string so a renamed type degrades to an unknown icon rather than silently becoming a different one, and the old single-string format still loads. |
| `panel.py` | The live party drawn beside the map, one card per character, with bars as well as the numbers so "who is hurt" is answered by looking; presentation only (the decoding is `live.py`), and it holds `ColumnSplitter`, the automapper tab's three draggable columns, because the width a card is drawn to is one of the widths it divides. |
| `paths.py` | Where settings, notes and the game disks live, on any platform; nothing here is Linux-specific. |
| `questlog.py` | The Quest Log beside the map — the City Council's books, including what is finished and still owed money, and the side quests an area script keeps for itself — read-only because every byte behind it is a plot flag; the decoding is `goldbox/commissions.py`. |
| `render.py` | Turns a `Geo` into drawing primitives; no Qt, so the window paints them, the tests assert on them and `to_svg` renders them with no emulator running, with doors drawn as doors and every edge drawn from both sides because wall art is not fully reciprocal and reciprocity would silently drop the one-way edges. |
| `rolls.py` | What the dice did, beside what the game printed: the d20, the number it had to reach and the dice the damage came off; no Qt. The attacker's numbers come from its own battle-roster block and never from the resident block at `$6C00`, which after a hit is the target's, and a roll is shown only where it can be tied to the game's message four ways. |
| `screen.py` | Reading the C64's 40x25 text screen from anything with a `read(addr, length)`, none of it VICE-specific: readers are passed as callables so a backend that batches or resumes around a burst keeps that decision to itself, and as a `Banks` pair where a backend can tell the chips from the RAM the VIC fetches, since the registers that say where the screen is are bytes of RAM whenever the game banks the I/O out mid-load. |
| `state.py` | What the automapper knows, with no Qt anywhere in it: the game saves no explored bitmap (`SAVEDGAME1` past `$83FF` is resident code and a graphics buffer), so `Exploration` tracks and persists what has been seen. |
| `target.py` | Where live bytes come from, as a contract of two methods so a second backend need not pretend it has breakpoints; `ViceTarget` holds one connection for the session and resumes after each burst. |
| `ui_noteeditor.py` | Generated from `noteeditor.ui` by `tools/generate/genui.py`; never edit it, since `--check` fails CI if it is out of step with the `.ui`. |
| `vice.py` | The VICE binary-monitor client: matches responses by request id, because VICE interleaves unsolicited events into the same stream and a naive client returns the previous request's data, and treats an open connection as a stopped machine, which is why it is a context manager. |
| `window.py` | The PyQt6 map window, deliberately thin: the geometry is in `render.py` and the knowledge is in `state.py`, and this paints primitives and forwards key presses, so the map can be developed and tested with no display. |
