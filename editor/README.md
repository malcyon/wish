# editor

The character editor's logic and dialogs, opened from `wish/window.py`; it imports nothing from `automap/`, so it works with no emulator installed, and `tests/wish/test_wish.py::test_editor_imports_nothing_live` greps every file here to keep that true.

| file | purpose |
|---|---|
| `__init__.py` | Empty. |
| `activeeffects.py` | The read-only panel of what is running on the save — the four effect arrays at `SAVEDGAME0`, one row per non-zero id, naming which character each is on or that it is the whole party; no duration is shown and nothing here writes a byte. |
| `binding.py` | Which widget edits which record field, and which fields must not be edited: widgets bind by `objectName` (`field_strength` edits the `strength` entry in `goldbox/layout.py`), and read-only is computed from three sources the project already maintains (the game recomputes it, we do not understand it, or the write would be silently dropped) so the list cannot go stale. |
| `changes.py` | What a save would write, phrased exactly as `wish --dry-run` prints it, compared against the bytes as read rather than a dirty flag so a value typed and typed back counts as no change. |
| `convert.py` | The File > Import and File > Export registry and its dialog: `Source.detect` reads a `.D64`, an Amiga `.adf`, a `SAVGAM<slot>.DAT`/`.PTY` file (the slot is the file's own letter) or a DOS save folder off a path, `destinations_for` answers only the directions in `DIRECTIONS`, `fresh_folder` names the `wish-YYYY-MM-DD` folder a conversion writes into, and `ConvertDialog` is the one dialog for every registered direction, with the DOS-to-C64 and C64-to-DOS rows derived from `C64_PAIRED` (`goldbox.dos_codec`'s `CONVERTS` filtered to the titles `goldbox.c64_port` names, which keeps Pools of Darkness out of a dialog with no C64 disk to write for it) and the Amiga rows from `goldbox.amiga_shared.CONVERTS`. |
| `dosimport.py` | `editor/convert.py`'s DOS-to-C64 conversion helper — `rehearse`, `GameFiles`, the two `NO_DISKS*` strings, `DROPPED_HEADING`, `name_warnings` and `log_unshown_losses` — where the `.d64` is built from nothing, so `rehearse` refuses outright when the player's game disks cannot be found rather than inventing bytes only they can supply (including, for Pool of Radiance, the creation menu the sheet portrait needs); tools and tests import it by this name. |
| `convert.ui` | The Qt Designer form for `ConvertDialog`, whose rows are found by `objectName` (`convert_source`, `convert_destination`, `convert_game`, `convert_folder`, `convert_destination_line`, `buttons`), with the game row hidden by `QFormLayout.setRowVisible` for a C64 destination and no report pane; compiled to `ui_convert.py` by `tools/generate/genui.py`. |
| `effects.py` | The ten trait slots at `0x0AD` as a ten-row table, named through `goldbox/traits.py`, coloured by confidence and edited through the Add and Remove buttons: `to_bytes` hands back the bytes it was given until Add or Remove replaces them, which keeps opening and saving an untouched save byte-identical, Add and Remove compact from slot 0 and leave a fill 255 where it sits in slot 9, and `warning` is `docs/133-active-effects.md`'s nonsense-combination table in code, colouring rather than refusing. |
| `enums.py` | Fields whose numbers have names, taken from `goldbox/yaml_io.py` so the CLI and the GUI cannot drift; race and class are functions of the title, not constants, because the lists differ between the six games. |
| `files.py` | Opening and saving without losing anybody's save disk: the editor writes back over the file you opened, made safe by an atomic write (temp file, fsync, rename) and a timestamped backup taken every time into a named folder. |
| `iconwidget.py` | The combat-icon editor, promoted onto the form as class `IconEditor`: two stacked 3x3 poses of `CHARPIC00` glyphs in multicolour text mode, offering the sixteen C64 colours and no others. |
| `inventory.py` | The sixteen item slots one character carries, with names spelled out; items live in `SAVEDGAME0`, not in the record, so a `.chr` export has none, and adding an item copies one of the real templates off the game disks rather than filling in fields, so the bytes we do not understand keep sane values. |
| `inventory.ui` | The Qt Designer form for the "Add an item" dialog. Compiled to `ui_inventory.py` by `tools/generate/genui.py`. |
| `palette.py` | The sixteen colours a C64 has, and no others. |
| `partspicker.py` | Pick an icon the way the game's own ICON menu does — a weapon and a head — with each option rendered as the icon you would end up with, so you choose a result rather than a number. |
| `partspicker.ui` | The Qt Designer form for the icon parts picker. Compiled to `ui_partspicker.py` by `tools/generate/genui.py`. |
| `roster.py` | The party list and the kinds of file it can come from -- a C64 disk, a DOS save, an Amiga save disk -- showing name, armour class and current hit points as the game's own party list prints them; which title a disk is stays a `Party.game`, and no filename is spelled out here. |
| `rosterview.py` | The party list's widget, promoted onto the form as class `RosterView`, and the one thing in the header that gives width up: above its minimum width it is exactly its five columns at their contents, below it `Name` absorbs the shortfall and truncates with an ellipsis, and only when `Name` has nothing left does the table scroll; the minimum is a constant and not a font metric, so the window's minimum width does not vary with the UI font. |
| `spellwidget.py` | Spells by name: the spellbook a character knows (`0x078`) and what is memorised (`0x020`), two kinds behind one three-method interface so the window handles them generically; neither consistency rule is enforced, the capacity is shown beside the list, an unknown spell is coloured, and the edit goes through either way. |
| `traitpicker.py` | The picker behind the traits box's Add button: every code the open title's table names except the fill byte, in two sections that say where the name came from ("seen in this game" for a code something on the player's own disks carries or the game's own routine was read for, "from the DOS table" for the ones only the third-party guide names), with a filter line that narrows it and drops an empty section, and a doubtful code coloured with its reason in the tooltip. |
| `traitpicker.ui` | The Qt Designer form for `TraitPicker`. Compiled to `ui_traitpicker.py` by `tools/generate/genui.py`. |
| `ui_convert.py` | Generated from `convert.ui` by `tools/generate/genui.py`; never edit it. |
| `ui_inventory.py` | Generated from `inventory.ui` by `tools/generate/genui.py`; never edit it. |
| `ui_partspicker.py` | Generated from `partspicker.ui` by `tools/generate/genui.py`; never edit it. |
| `ui_traitpicker.py` | Generated from `traitpicker.ui` by `tools/generate/genui.py`; never edit it. |
| `window.py` | Binds the character sheet's widgets, which live in `wish/window.ui` (`docs/146-unified-ui.md`), to `goldbox/layout.py` fields by `objectName`, so the form can be rearranged, regrouped or relabelled in Qt Designer without a line of this file changing; `EditorBinding` and `RowSplitter` are what `wish/window.py` imports from it. |
