# editor

The character editor GUI. Opens a `.D64` and writes it back; imports nothing
from `automap/`, so it works with no emulator installed anywhere —
`tests/test_wish.py::test_editor_imports_nothing_live` greps every file here to
keep that true.

The character sheet's own form moved into `wish/window.ui`, the single
unified layout — see `docs/146-unified-ui.md`. There is no standalone
`python -m editor` any more; this package is the sheet's logic and dialogs,
opened from `wish/window.py`.

| file | purpose |
|---|---|
| `__init__.py` | Empty. |
| `activeeffects.py` | The read-only panel of what is running on the **save** -- the four effect arrays at `SAVEDGAME0`, one row per non-zero id, naming which character each is on or that it is the whole party. No duration is shown and nothing here writes a byte. |
| `binding.py` | Which widget edits which record field, and which fields must not be edited. Widgets bind by `objectName` (`field_strength` edits the `strength` entry in `goldbox/layout.py`), and read-only is *computed* from three sources the project already maintains — the game recomputes it, we do not understand it, or the write would be silently dropped — so the list cannot go stale. |
| `changes.py` | What a save would write, phrased exactly as `wish --dry-run` prints it. Compares against the bytes as read rather than against a dirty flag, so a value typed and typed back counts as no change. |
| `convert.py` | `#52 (File ▸ Import and File ▸ Export for every direction the library supports)`'s registry and its dialog. **Off unless `WISH_EXPERIMENTAL_CONVERT=1`** — lifted once, on 2026-09-07, and put back the same night once `File ▸ Convert…` was found still opening a file picker before the window, since fixed by `#412 (File ▸ Convert demands a save in a file picker before it will show you the Convert window)`. `dosimport.py`'s submenu, which duplicated this, is gone (`#52 (File ▸ Import and File ▸ Export for every direction the library supports)`'s own step 5). The registry: `Source.detect` reads a `.D64`, an Amiga `.adf`, a `SAVGAM<slot>.DAT`/`.PTY` file (the slot is the file's own letter, so the dialog has no separate slot row) or a DOS save folder off a path; `destinations_for` answers only the directions in `DIRECTIONS`; `fresh_folder` names the `wish-YYYY-MM-DD` folder a conversion writes into. `DIRECTIONS`' DOS → C64 and C64 → DOS rows are each derived from `C64_PAIRED`, which is `goldbox.dos`'s own `CONVERTS` filtered to the titles `goldbox.games` names — today Pool of Radiance, Curse of the Azure Bonds and Secret of the Silver Blades, both ways. The filter is what keeps Pools of Darkness out of a dialog that has no C64 disk to write for it, since that title reads and writes as a DOS record now and has no C64 release at all — and both Amiga rows from `goldbox.amiga.CONVERTS`, Pool of Radiance alone. `ConvertDialog` is one dialog for every registered direction: a source row, a destination combo, a game-files row shown only for a DOS destination, a write-to-folder row carrying its own `Destination:` line naming the folder alone. **The report pane is gone outright, 2026-09-10** -- Donald, having already asked for its `Convert Log` heading removed and then finding the box still standing under it: *"the box under it has to be removed, too. That was the entire point."* What it used to draw now goes to three places: a real refusal -- `CANNOT_CONVERT` or a `DosRecordError`'s own message, a source the player actually chose and Wish cannot convert -- and a name DOS's own fifteen-character field could not hold whole reach a modal `QMessageBox` (`_maybe_warn`); `NO_DISKS`, `NO_DISK`, `NO_FOLDER` and `NO_GAME_FOLDER` name a row the player has simply not filled in yet and reach no modal at all since `#52`'s own comment of 2026-09-10 -- the disabled Convert button already says as much, and popping one on the very next field after `From` told a player they had made a mistake that was actually inevitable (`_SILENT_BLOCKS`); a magic-user memorising more spells than the destination title's own slots (`#508 (A converted magic-user loses memorised spells on the way to DOS, because our table says a title has fewer slots than the engine gives it)`) and a spell id outside the destination's own book (`#509 (A converted spellbook drops ids the destination title is said not to have, though both platforms are the same game)`) are bugs rather than platform limits and reach the debug log instead, alongside the drop list `#416 (The live Convert dialog never shows a DOS→C64 conversion's own messages or capacity-ceiling warnings)`'s own ruling already sent there. `exports.py`'s `Source` retires into this one at step 5. |
| `dosimport.py` | No window any more — `File ▸ Import ▸ DOS Save Folder…` and its `DosImportDialog` are gone (`#52 (File ▸ Import and File ▸ Export for every direction the library supports)`'s step 5, 2026-09-07). What is left is the library `File ▸ Convert…` calls: `rehearse` (`goldbox/dos.py`'s DOS → C64 converter, run in memory with nothing written), `pane_text` (the messages, then the capacity-ceiling losses), `GameFiles` and the two `NO_DISKS*` refusal strings. **`pane_text` stopped drawing `report.dropped` on 2026-09-08**: Donald ruled that a route which drops something is not offered to a player as though it worked (`.claude/rules/conversions.md`), so the drop list goes to the debug log (`wish/debuglog.py`, off unless `WISH_DEBUG` is set) instead of the pane. `EditorBinding.game_files_for_import` and `adopt_conversion` in `editor/window.py` still call in here but are no longer reached from any menu. `dropped_text` has no caller left at all — kept rather than deleted because removing it was not this step's to do. |
| `convert.ui` | The Qt Designer form for `ConvertDialog`. Rows found by `objectName`: `convert_source`/`convert_choose_source`, `convert_destination`, `convert_game`/`convert_choose_game` (the `game_row` `QHBoxLayout` is hidden with `QFormLayout.setRowVisible` for a C64 destination), `convert_folder`/`convert_choose_folder`/`convert_destination_line`, `buttons`. No `convert_report` or `label_report` any more (2026-09-10) -- what they drew is a modal `QMessageBox` now. Compiled to `ui_convert.py` by `tools/genui.py`. |
| `effects.py` | The ten trait slots at `0x0AD` as a ten-row table, named through `goldbox/traits.py` and coloured by confidence, and edited through the Add and Remove buttons. `to_bytes` hands back the bytes it was given until Add or Remove replaces them, which is what keeps opening and saving an untouched save byte-identical; Add and Remove compact from slot 0 and leave a fill 255 where it sits in slot 9. `warning` is `docs/133-active-effects.md`'s "nonsense combination" table in code -- a monster's attack form on a character, a code with no handler, a code nobody has named, the same code twice -- and it colours rather than refuses, the spellbook precedent. |
| `enums.py` | Fields whose numbers have names, taken from `goldbox/yaml_io.py` so the CLI and the GUI cannot drift. Race and class are *functions* of the title, not constants, because the lists differ between the six games. |
| `exports.py` | **Off unless `WISH_EXPERIMENTAL_EXPORT=1`** -- the Export submenu is not built otherwise, because every string in the file is an unapproved placeholder. The windows over `goldbox.dos.write_dos_save` and `goldbox.amiga.export_party`: a C64 party written out to a DOS save directory or to Amiga `.pc` files. An export has no backup behind it -- it writes into a folder the editor does not own -- so the guarantee is the other one: the conversion is rehearsed into a scratch directory, and the pane names every file the write would replace and every one it would remove (`#68 (A second conversion into the same folder leaves the first party's extra characters behind)`) before the button exists to press. |
| `exports.ui` | The Qt Designer form for the export dialog. Compiled to `ui_exports.py` by `tools/genui.py`. |
| `files.py` | Opening and saving, and not losing anybody's save disk. The editor writes back over the file you opened, which is only defensible because the write is atomic (temp file, fsync, rename) and a timestamped backup is taken every time into a folder that is named rather than guessed. |
| `iconwidget.py` | The combat-icon editor, promoted onto the form as class `IconEditor`. Draws the genuine article — two stacked 3x3 poses of `CHARPIC00` glyphs in multicolour text mode — and offers the sixteen C64 colours and nothing else, because a general colour dialog would offer colours the machine cannot show. |
| `inventory.py` | The sixteen item slots one character carries, with names spelled out. Items live in `SAVEDGAME0`, not in the record, so a `.chr` export has none. Adding an item means copying one of the 163 real templates off the game disks, never filling in fields, so the bytes we do not understand keep sane values. |
| `inventory.ui` | The Qt Designer form for the "Add an item" dialog. Compiled to `ui_inventory.py` by `tools/genui.py`. |
| `palette.py` | The sixteen colours a C64 has, and no others. |
| `partspicker.py` | Pick an icon the way the game's own ICON menu does — a weapon and a head — with each option rendered as the icon you would end up with, so you choose a result rather than a number. Replaces a per-cell glyph picker that could build a figure with two heads and no legs. |
| `partspicker.ui` | The Qt Designer form for the icon parts picker. Compiled to `ui_partspicker.py` by `tools/genui.py`. |
| `roster.py` | The party list, and the three kinds of file it can come from. Shows name, armour class and current hit points — exactly what the game's own party list prints, established by disassembling all 64 call sites into its string printer. Which title a disk is stays a `Party.game`; no filename is spelled out here. |
| `rosterview.py` | The party list's widget, promoted onto the form as class `RosterView`. The one thing in the header that gives width up: above its floor it is exactly its five columns at their contents, below it `Name` absorbs the shortfall and elides, and only when `Name` has nothing left does the table scroll. The floor is a constant and not a font metric, because the header does not scroll and so the roster's minimum is a floor under the whole window -- which is what used to make that floor follow the UI font (`#71 (Character draws on top of itself when the header is squeezed to its floor)`, `#41 (The window's minimum width is 1546px on Windows and 1071px on Linux)`). |
| `spellwidget.py` | Spells by name: the spellbook a character knows (`0x078`) and what is memorised (`0x020`), two shapes behind one three-method interface so the window handles them generically. Neither consistency rule is enforced — the capacity is shown beside the list and an unknown spell is coloured, and the edit goes through either way. |
| `traitpicker.py` | The picker behind the traits box's Add button: every code the open title's table names bar the fill byte, in two sections that say **where the name came from** rather than how sure we are — "seen in this game" for a code something on the player's own disks carries or the game's own routine was read for, "from the DOS table" for the ones only the third-party guide names. Donald's D4, 2026-09-07: the whole table, not `docs/107-roster-and-notes.md` section 8's cut at id 64. A filter line narrows it and drops a section that has nothing left; a doubtful code is coloured with its reason in the tooltip. |
| `traitpicker.ui` | The Qt Designer form for `TraitPicker`. Compiled to `ui_traitpicker.py` by `tools/genui.py`. |
| `ui_convert.py` | **Generated** from `convert.ui`, the same way. |
| `ui_exports.py` | **Generated** from `exports.ui`, the same way. |
| `ui_inventory.py` | **Generated** from `inventory.ui`, the same way. |
| `ui_partspicker.py` | **Generated** from `partspicker.ui`, the same way. |
| `ui_traitpicker.py` | **Generated** from `traitpicker.ui`, the same way. |
| `window.py` | Binds the character sheet's widgets — now part of `wish/window.ui` — to `goldbox/layout.py` fields. Finds them by `objectName`, so the form can be rearranged, regrouped or relabelled in Qt Designer without a line of this file changing. `EditorBinding` and `RowSplitter` are what `wish/window.py` imports from it. |
