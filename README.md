# wish

Wish is a character editor for the **Commodore 64** version of *Pool of Radiance*
(SSI, 1988). 


## AI Usage

This project is entirely generated by Claude Code.


## Requirements

* Python 3.12 or later
* A Pool of Radiance save disk (`.D64`). A game disk is optional but
  recommended — it is what turns item and spell numbers into names.
* For the automapper only: VICE, and the game actually running in it.

## Setting up

Everything installs into one virtual environment:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,gui,automap]"
```

That gives you both programs at once — the `wish-cli` tool and the `wish`
window, which holds the character editor and the live automapper in two tabs.
`-e` installs in place, so edits to the source take effect without
reinstalling.

Activate the environment and the commands are on your path:

```sh
source .venv/bin/activate
wish-cli --export PORSAVE.D64 --output party.yaml
wish PORSAVE.D64            # the window, on the character sheet
wish --tab map              # the window, on the map
```

`wish-editor` and `wish-automap` still work: they are the same window, opened
on the tab the name implies.


## CLI Usage

Export a party, edit the file, write it to a new disk:

```sh
source .venv/bin/activate
wish-cli --export PORSAVE.D64 --output party.yaml
vi party.yaml
wish-cli --import party.yaml --output PORSAVE-EDITED.D64
```

See what an import *would* change without writing anything:

```sh
wish-cli --import party.yaml --dry-run
```

### Options

| Flag | Meaning |
|---|---|
| `--export SAVE.D64` | read this save disk and write YAML |
| `--import PARTY.YAML` | read this YAML and write a new save disk |
| `--output`, `-o` | the file to write |
| `--original-save`, `-s` | `--import` only: the disk to build on. Defaults to the one recorded in the YAML at export, so it is rarely needed |
| `--game-disk` | a game disk, used to name items and spells |
| `--dry-run`, `-n` | `--import` only: report the changes without writing |

### Finding a game disk

Item and spell names come from the game's own data files, so a game disk is
needed to show them. It is looked for in this order:

1. `--game-disk`
2. the `POR_GAME_DISK` environment variable
3. any `POOL*.D64` in the same directory as the save disk

The third covers the usual case, so most of the time no configuration is needed.


## Character Editor

```sh
source .venv/bin/activate
wish PORSAVE.D64
```

The **Character Editor** tab. A roster on the left showing what the game's own party list shows — name,
armour class, hit points, with the wounded in red — and the character sheet on
the right. **Save writes back to the file you opened**, after copying it to a
timestamped backup under `backups/`; a save that changes nothing writes nothing.

The sheet is one scrolling page of titled boxes — Identity, Abilities, Combat,
Experience and levels, Thief skills, Money, Appearance, Inventory, Spells — and
a box nothing in it applies to is hidden, so a fighter is shown no spellbook
and no thief skills rather than a page of zeros.

Fields the game recomputes, fields nobody has decoded, and fields that live
past the 256 bytes a save slot holds are all shown greyed, with the reason in
the tooltip. The combat icon is real pixel art — two poses, multicolour, click
a cell for the sixteen C64 colours.


### Editing the form

The character editor's layout is a Qt Designer file, `editor/character.ui`,
loaded at runtime — so rearranging fields needs no rebuild. Qt Designer comes
from the system, not the venv:

```sh
sudo apt install qt6-tools-dev-tools
/usr/lib/qt6/bin/designer editor/character.ui
```

Widgets bind to record fields by `objectName`, so moving one on the form changes
nothing else. See [`docs/97-editor.md`](docs/97-editor.md).


## Automapper

Draws the map as you walk, reading the running game out of VICE. 

### Configuring VICE

The automapper reads the running game through **VICE's binary monitor**, a debug
socket VICE does not open by default. 

**1. Enable the monitor.** Either add these to the `[C64SC]` section of VICE's
settings file, or pass the equivalent flags when you launch:

```ini
BinaryMonitor=1
BinaryMonitorAddress="127.0.0.1:6502"
```

```sh
x64sc -binarymonitor -binarymonitoraddress 127.0.0.1:6502
```

**Close VICE before editing the file** — it rewrites it on exit and will discard
changes made while it is running.

| platform | settings file |
|---|---|
| Windows | `%APPDATA%\vice\vice.ini` |
| macOS | `~/Library/Application Support/vice/vicerc` |
| Linux | `~/.config/vice/vicerc` |
| Linux, Flatpak | `~/.var/app/net.sf.VICE/config/vice/vicerc` |

**2. Flatpak only — grant network access.** 
On Linux, if you have VICE installed via a flatpak, you'll need to grant it extra permissions.

```sh
flatpak override --user --share=network net.sf.VICE
```

**3. Start the game however you normally do**, and run:

```sh
source .venv/bin/activate
wish --tab map
```

The window attaches on its own and waits if there is nothing to attach to;
only the tab you are looking at reads the machine.

| key / action | |
|---|---|
| **Fog of war** checkbox, or `R` | hide squares the party has not seen. On by default. |
| click a square | attach a note to it |


### Wish Config Files
| | Windows | macOS | Linux |
|---|---|---|---|
| settings | `%APPDATA%\wish\` | `~/Library/Application Support/wish/` | `~/.config/wish/` |
| notes, explored squares | `%LOCALAPPDATA%\wish\` | `~/Library/Application Support/wish/` | `~/.local/share/wish/` |

Settings are one small JSON file you can read and edit. Notes are kept per area.

Explored squares are remembered per area, so leaving and coming back keeps what
you had mapped. `wish --forget AREA` clears them for one map (or `ALL`)
and keeps any notes.

**Finding the game disks.** `$POR_DISKS` wins if set; otherwise the map looks for
a directory holding `POOL*.D64` in the usual places — the current directory, your
home, `Documents`, `Games`, `Downloads` — or pass `--disks`.

To draw a map without an emulator at all:

```sh
source .venv/bin/activate
wish --svg GEO00 new-phlan.svg
```

`GEO00` is New Phlan; [`docs/88-map-files.md`](docs/88-map-files.md) lists all
twenty-nine and names the nine Phlan city blocks.
